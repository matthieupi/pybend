#### Key Findings / Bugs Documented
- Product model uses {"*": "authenticated"} wildcard access (no per-action rules, no owner check). Any authenticated user can update/delete any product.
- Product list endpoint is public (200 OK without auth), but product detail requires auth (403 without token).
- Comment and reply API responses are double-encoded JSON (model_dump_json returns string, FastAPI wraps again).
- Comment creation via model_dump_json returns id:0 (model_dump_json called before save).
- Rapid navigation triggers "[undefined] Assertion error: Callback for ... is not a function" from NTT actor system (known race condition).
- Registration endpoint accepts empty name/email/password (no server-side validation for these fields).
- Join model is named ProductComment (not Comment), so $schema URL contains /ProductComment.
- user_owner field in depth=1 responses is an href string (e.g., "http://localhost:5000/users/1") not a numeric ID.

#### Commands Run
- Individual file runs: npx playwright test --config=tests/e2e/playwright.config.js tests/e2e/{file}.spec.js
- Full suite run: npx playwright test --config=tests/e2e/playwright.config.js tests/e2e/flow-*.spec.js
- Result: 200 passed (14.9m), 0 failed

#### Tradeoffs / Assumptions
- Tests use Date.now() timestamps for unique test data to avoid conflicts between runs.
- Known NTT actor system race conditions during rapid navigation are filtered from error assertions (documented with BUG comments).
- Tests adapted to actual API behavior rather than planned behavior (e.g., Product access rules differ from plan assumptions).
- Shadow DOM access uses .evaluate() with shadowRoot.querySelector() patterns throughout.
