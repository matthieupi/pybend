# API Routes & Authentication Patterns Audit

**Date**: 2026-03-26
**Scope**: Route generation, auth enforcement, request handling, streaming, response formats
**Focus**: Consistency between Level 1/2 and Level 3 routing, framework bypass detection

---

## Executive Summary

Overall consistency score: **7.5/10**. CRUD routes, serialization, and `@expose_route` adoption are strong. Key issues: **streaming format divergence** between Level 1/2 and Level 3, **hand-rolled routes bypassing `@expose_route`** in veille/chat, **error response format inconsistency**, and **field-level access declared but not enforced**.

## Route Generation

### Level 1/2 -- Direct FastAPI (`routes_fastapi.py`)

Routes generated by `register_routes()` via factory functions:
- `make_create_instance()` -- POST /{tablename}
- `make_get_all_instances()` -- GET /{tablename}
- `make_get_instance()` -- GET /{tablename}/{id}
- `make_update_instance()` -- PUT /{tablename}/{id}
- `make_delete_instance()` -- DELETE /{tablename}/{id}
- `make_get_schema()` -- GET /{ClassName} (public)
- `make_custom_post()` -- Custom @expose_route methods

**Auth**: Single-pass via `_build_context()` + `_resolver.authorize()`
**User injection**: `_resolve_user(type_hint, request)` resolves JWT dict to full User instance
**Protected fields**: Auto-injection on create, stripping on update

### Level 3 -- Actor Routing (`network_api.py`)

Same HTTP route structure, but each request becomes a TX message:
- Schema: `TX(name='schema', source='api', target=tablename)`
- CRUD: `TX(name='create'|'get'|'list'|'update'|'delete', ...)`
- Custom: `TX(name=method_name, ...)`
- All pass `meta={'user': user, 'model_cls': model_cls}`

**Auth**: Two-tier:
- **Tier 1**: `auth_interceptor` on `NetworkAPI.request()` -- fast gate at protocol boundary
- **Tier 2**: `ActorModel._authorize()` in `handler_crud()` -- full ABAC with resource instance

### WebSocket Bridge (`network_ws.py`)

Bidirectional TX translation:
```
Frontend UPPERCASE -> Backend lowercase
SCHEMA -> schema, CREATE -> create, READ -> list
UPDATE -> update, DELETE -> delete, LOAD -> schema
```

**Issues**: Decodes JWT again independently instead of using framework middleware (duplicate JWT validation).

## @expose_route Usage Audit

### Pattern Catalog

**Pattern 1: Simple Instance Method**
```python
@expose_route('/comment', methods=['POST'])
def comment(self, comment: Comment, user: User = None) -> Comment:
```
Route: `POST /products/{id}/comment`

**Pattern 2: Streaming Instance Method**
```python
@expose_route('/countdown', methods=['POST'], stream=True, access=ANYONE)
async def countdown(self, n: int = 5):
    yield {'count': i, 'message': f'Counting down: {i}'}
```
Route: `POST /products/{id}/countdown` (SSE)

**Pattern 3: Streaming with Event Schema**
```python
@expose_route('/analyze', methods=['POST'], stream=True, access=AUTHENTICATED,
              events={'text': TextChunk, 'tool_call': ToolCallEvent, ...})
async def analyze(self, user=None):
    async for chunk in self.agentic_stream(...):
        yield chunk
```

**Pattern 4: Class Method (No Self)**
```python
@expose_route('/report', methods=['GET'], access=AUTHENTICATED)
def report(run_id: int) -> dict:
```
Route: `GET /runs/report?run_id=N` (no `{id}` in path)

### Coverage
- 49 files use `@expose_route`
- All custom methods use the decorator (no bypasses found)
- Parameters consistent (methods=, access=, stream=, events=)

## Response Format Analysis

### CRUD Responses

| Operation | Level 1/2 | Level 3 | Consistent? |
|-----------|-----------|---------|-------------|
| CREATE (201) | Single instance with $schema, $id | `result.model_response()` | Yes |
| READ (200) | Single instance with $schema, $id | `result.model_response()` | Yes |
| LIST (200) | `{data: [...], meta: {...}}` or plain array | Same | Yes |
| UPDATE (200) | Single instance with $schema, $id | `result.model_response()` | Yes |
| DELETE (200) | `{message: "Deleted successfully"}` | `{'deleted': entity_id}` | **NO** |

**Delete response inconsistency**: Level 1/2 returns `{message: "..."}`, Level 3 returns `{'deleted': id}`.

### List Response Ambiguity

Both levels can return either:
- `{data: [...], meta: {total, limit, offset, has_more}}` (paginated)
- `[...]` (plain array -- unpaginated)

**Issue**: No documented contract for when each format is used. Frontend must handle both.

### Error Responses

| Source | Format |
|--------|--------|
| Level 1/2 HTTPException | `{detail: "Access denied"}` |
| Level 3 TX error | `{is_error: true, data: {code: 403, message: "..."}}` |
| Level 3 via HTTP | Converted to `{detail: "..."}` via `_response_or_raise()` |

**Issue**: Error format varies depending on transport layer (HTTP vs WS). WebSocket clients see raw TX errors, HTTP clients see FastAPI-style errors.

## Streaming Format Divergence (CRITICAL)

### Level 1/2 Streaming

```
event: chunk
data: {"count": 5, "message": "Counting down: 5"}

event: done
data: {}
```

Simple chunk data. No envelope.

### Level 3 Streaming

```
event: chunk
data: {"name": "countdown", "source": "api", "target": "products",
       "data": {"count": 5, "message": "Counting down: 5"},
       "meta": {"req": "...", "stream": true, "seq": 0},
       "timestamp": "2026-03-26T..."}

event: done
data: {"name": "countdown", ..., "meta": {"stream_end": true, "seq": 5}, ...}
```

Full TX envelope per chunk.

### Impact
- Frontend must handle two completely different streaming protocols
- NTTStream.js must detect which format is in use
- Event naming: Level 1/2 uses `chunk|done`, Level 3 uses `chunk|done|error`

### Level 1/2 Missing `event: error`
Level 1/2 has no error event for streaming -- errors during iteration go unhandled at the SSE level.

## Authentication Deep Dive

### JWT Middleware (`backend.py`)
- Pure ASGI (no buffering that breaks SSE)
- Extracts `x-access-token` header
- Sets `request.state['user']` = payload dict
- Exempt: `/login`, `/register`, `/docs`, static file extensions

### Tier 1 Auth (Level 3 -- `auth_interceptor.py`)
```
schema   -> Always pass
create   -> Full rule check
get      -> Identity gate (OWNER deferred to Tier 2)
list     -> Compute sql_filter from rules
update   -> Full rule check
delete   -> Full rule check
Custom   -> Check @expose_route(access=...)
```

### Tier 2 Auth (Level 3 -- `actor_model.py`)
- Called AFTER fetching resource instance
- Enables OWNER rules requiring actual resource
- Internal messages (no `tx.meta['user']`) pass through

### User Injection Asymmetry

| Level | What Custom Methods Receive |
|-------|-----------------------------|
| 1/2 | Full User instance (resolved via `_resolve_user()`) |
| 3 | Raw dict from JWT payload |

**Issue**: Custom methods must handle both User instances and dicts depending on routing level.

## Field-Level Access (Declared but Not Enforced)

```python
# Declared in model:
price: CurrencyField = Field(..., json_schema_extra={
    'access': {'view': 'anyone', 'edit': 'admin'}
})
```

- Schema carries the `access` metadata to the frontend
- Frontend UI respects it (Formidable hides/shows fields)
- **Backend does NOT enforce field-level edits** -- all fields accepted in PUT requests
- No field filtering in `routes_fastapi.py` or `actor_model.py`

## Issues Summary

| # | Issue | Severity | Impact |
|---|-------|----------|--------|
| 1 | Streaming format divergence (Level 1/2 vs 3) | CRITICAL | Frontend protocol split |
| 2 | Veille document routes bypass @expose_route | HIGH | Duplicate auth, inconsistent patterns |
| 3 | Delete response format inconsistent | MEDIUM | `{message}` vs `{deleted: id}` |
| 4 | List response ambiguity (paginated vs plain) | MEDIUM | Frontend must handle both |
| 5 | Error format varies by transport | MEDIUM | WS vs HTTP clients see different errors |
| 6 | User injection asymmetry (User vs dict) | MEDIUM | Methods must handle both types |
| 7 | Field-level access not enforced | MEDIUM | Schema declares it, backend ignores it |
| 8 | Duplicate JWT decode in WebSocket bridge | LOW | Two JWT validation implementations |
| 9 | Level 1/2 missing streaming error event | LOW | No `event: error` for stream failures |

## Recommendations

### Priority 1: Standardize Streaming Format
Decide on one SSE format and apply consistently:
- Option A: Both levels stream simple chunks (Level 3 extracts `data` from TX)
- Option B: Both levels stream TX envelopes (Level 1/2 wraps in envelope)
- Option C: Document both protocols, let NetworkAdapter.js handle translation

### Priority 2: Convert Veille Document Routes
Move file upload/download/delete to `@expose_route` methods on Organization model.

### Priority 3: Fix Delete Response
Standardize on one format: `{'deleted': entity_id}` or `{message: "Deleted successfully"}`.

### Priority 4: Document Streaming Contracts
- SSE event names: `chunk`, `done`, `error`
- Chunk data format per level
- Termination protocol
- Error handling during streams

### Priority 5: Enforce Field-Level Access
Validate field-level access rules in `model_response()` or route layer, not just frontend UI.

### Priority 6: Unify User Injection
Level 3 custom methods should receive the same User instance as Level 1/2.
