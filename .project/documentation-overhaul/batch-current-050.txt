681: **Lifecycle:**
682: 1. Setting `ref` sends ATTACH to N3TX (routed to DynClass then to instance)
683: 2. N3TX instance responds with DESCRIBE (schema + data)
684: 3. Item renders using `Formidable.getForm()`
685: 4. Click pencil -> edit mode (inputs). Click save -> sends UPDATE to N3TX.

722: ## 10. Custom Methods
723: 
724: If your backend model defines custom methods (e.g., `comment` on Product),
725: they appear in the JSON schema under `methods` and are auto-generated as
726: methods on the DynClass prototype:
727: 
728: ```
729: Backend schema:
730: {
731:   "methods": {
732:     "comment": {
733:       "parameters": {
734:         "name":        { "type": "string" },
735:         "description": { "type": "string" }
736:       }
737:     }
738:   }
739: }
740: ```
741: 
742: ```js
743: // Call from code:
744: const product = N3TX.get('Product/1');
745: product.comment({ name: "Great!", description: "Love this product" });
746: 
747: // Under the hood:
748: // TX { name: 'comment', target: http://.../products/1 }
749: // -> NetworkAdapter maps unknown name -> POST /products/1/comment
750: ```

830: ## 12. Message Protocol Cheat Sheet
831: 
832: ### TX Message Format
833: 
834: ```js
835: {
836:   name:   "EVENT_NAME",       // Handler method to invoke (UPPERCASE)
837:   source: "sender-address",   // Who sent this
838:   target: "receiver-address", // Who should receive this (addr or URL)
839:   data:   { ... },            // Payload
840:   meta:   { ... },            // Metadata: { remote, inbox, ... }
841:   tst:    1702000000000,      // Timestamp
842:   hash:   "abc123"            // Content hash
843: }
844: ```
845: 
846: ### Key `meta` Fields
847: 
848: | Field | Type | Effect |
849: |-------|------|--------|
850: | `remote` | `bool` | Marks message for/from network transport |
851: | `inbox` | `string` | Overrides the response event name (e.g., response arrives as UPDATE instead of READ) |
852: 
853: ### Complete Message Reference
854: 
855: | Name | Direction | Purpose |
856: |------|-----------|---------|
857: | `ATTACH` | Component -> N3TX -> DynClass/instance | "I want to connect to this model/entity" |
858: | `SCHEMA` | N3TX <-> Backend | Fetch/receive JSON schema |
859: | `READ` | DynClass -> Backend | Fetch all records |
860: | `DESCRIBE` | N3TX instance -> Component | "Here's my schema and current data" |
861: | `UPDATE` | Any <-> Any | Update entity data (local or remote) |
862: | `CREATE` | DynClass -> Backend | Create a new record |
863: | `DELETE` | N3TX instance -> Backend | Delete a record |
864: | `CONNECT` | Component -> Matrix | Connect to a type (theme/role routing) |
865: | `ERROR` | NetworkAdapter -> Source | Network error response |
866: 
867: ### Response Flow (meta.inbox)
868: 
869: The `meta.inbox` pattern lets you control what event name the response arrives as:
870: 
871: ```
872: Request:  { name: READ, meta: { inbox: 'UPDATE' } }
873:                                           |
874: Response: { name: UPDATE }  <-------------+
875:                   (not READ)
876: ```
877: 
878: This is how DynClass gets list data back as an UPDATE event to trigger re-rendering.

901: ## 14. Troubleshooting
902: 
903: | Symptom | Likely Cause | Fix |
904: |---------|-------------|-----|
905: | List is empty / no cards | Backend not running or wrong `API_URL` | Check `config.js` API_URL matches backend port |
906: | "CORS error" in console | Backend doesn't allow frontend origin | Add CORS middleware to FastAPI backend |
907: | Cards render but show "Placeholder" | Schema loaded but READ failed | Check backend `/tablename` endpoint returns an array |
908: | Edit + Save does nothing | N3TX update flow not connected | Check browser console for TX routing errors |
909: | `$schema` assertion error on save | Response bypassing N3TX, going directly to Item | Hard-refresh browser (Ctrl+Shift+R) to clear cached JS |

911: ### Debugging Tips
912: 
913: 1. **Enable verbose logging** — set `LOGGING: 3` and `LOGEVENTS: true` in config.js
914: 2. **Watch TX flow** — every message logs to console with source -> target
915: 3. **Inspect actor tree** — `matrix.children` in console shows all registered classes
916: 4. **Check N3TX state** — `N3TX.get('Product')` returns the DynClass, `.schema` for schema, `.children` for instances
