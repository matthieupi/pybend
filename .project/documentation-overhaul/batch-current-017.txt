525: ## Comment Model
526: 
527: Comments on products. The Comment model uses `id` as its primary key field (consistent with Product and User).
528: 
529: ### Endpoints
530: 
531: | Method | Path | Purpose |
532: |--------|------|---------|
533: | GET | `/Comment` | Get schema |
534: | POST | `/products/{parent_id}/comments` | Create comment for product |
535: | GET | `/products/{parent_id}/comments` | List product's comments |
536: | GET | `/products/{parent_id}/comments/{id}` | Get specific comment |
537: | PUT | `/products/{parent_id}/comments/{id}` | Update comment |
538: | DELETE | `/products/{parent_id}/comments/{id}` | Delete comment |
539: | POST | `/products/{parent_id}/comments/{id}/like` | Toggle like on comment |
540: | POST | `/products/{parent_id}/comments/{id}/reply` | Reply to comment |
541: 
542: **Note**: Comments are a nested resource under Products. Like and reply are custom methods on comment instances.
543: 
544: ### Schema
545: 
546: ```json
547: {
548:   "$schema": "http://localhost:8000/Schema",
549:   "$id": "http://localhost:8000/Comment",
550:   "type": "object",
551:   "properties": {
552:     "id": {
553:       "type": "integer"
554:     },
555:     "name": {
556:       "type": "string",
557:       "description": "Comment title"
558:     },
559:     "description": {
560:       "type": "string",
561:       "description": "Comment text",
562:       "default": ""
563:     },
564:     "user_owner": {
565:       "type": "integer",
566:       "description": "ID of user who created comment"
567:     }
568:   },
569:   "required": ["name", "user_owner"]
570: }
571: ```
572: 
573: ### Field Details
574: 
575: | Field | Type | Required | Constraints | Description |
576: |-------|------|----------|-------------|-------------|
577: | `id` | integer | No (auto) | Read-only | Unique identifier |
578: | `name` | string | Yes | - | Comment title |
579: | `description` | string | No | - | Comment text |
580: | `user_owner` | integer | Yes (protected) | Must be valid User ID | Comment author (auto-injected from JWT) |
581: | `parent_id` | integer | No | Ref['self'] | Parent comment ID for nesting (replies) |

941: ## Working with Foreign Keys
942: 
943: ### Understanding Foreign Key Fields
944: 
945: When a model has a foreign key:
946: 
947: ```python
948: class Comment(ProtoModel):
949:     user_owner: Ref[User]
950: ```
951: 
952: **In the API**:
953: - Requests send the **integer ID**: `"user_owner": 1`
954: - Responses return the **integer ID**: `"user_owner": 1`
955: 
956: **To get the full related object**, make a separate request:
957: 
958: ```typescript
959: // 1. Get comment
960: const comment = await fetch('/products/1/comments/1').then(r => r.json());
961: // { $schema: "...", $id: "...", id: 1, user_owner: 1, ... }
962: 
963: // 2. Get the user
964: const user = await fetch(`/users/${comment.user_owner}`).then(r => r.json());
965: // { $schema: "...", $id: "...", id: 1, name: "Alice", email: "alice@example.com" }
966: ```
967: 
968: ### Helper Function for Resolving Foreign Keys
969: 
970: ```typescript
971: async function resolveRelations<T>(
972:   obj: T, 
973:   relations: Record<string, string>
974: ): Promise<T> {
975:   const resolved = { ...obj };
976:   
977:   for (const [field, endpoint] of Object.entries(relations)) {
978:     const id = (obj as any)[field];
979:     if (id) {
980:       (resolved as any)[`${field}_obj`] = await fetch(`${endpoint}/${id}`)
981:         .then(r => r.json());
982:     }
983:   }
984:   
985:   return resolved;
986: }
987: 
988: // Usage
989: const comment = await fetch('/products/1/comments/1').then(r => r.json());
990: 
991: const enriched = await resolveRelations(comment, {
992:   user_owner: '/users'
993: });
994: 
995: console.log(enriched.user_owner); // 1
996: console.log(enriched.user_owner_obj); // { $schema: "...", $id: "...", id: 1, name: "Alice", ... }
997: ```
