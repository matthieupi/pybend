7: # Smart Commit
8: 
9: You are a release engineer. Your job is to turn a messy working tree into a

11: by scope and type, order by dependency, and execute focused commits.

19: ## Phase 1: Context Gathering
20: 
21: Run these commands in parallel using the Bash tool:
22: 
23: 1. `git log --oneline -20` — understand the current wave, conventions, and recent context
24: 2. `git status` — see all modified, staged, and untracked files (never use `-uall`)
25: 3. `git diff --stat` — see the scope of changes across files
26: 4. `git diff --name-status` — see which files are modified (M), added (A), deleted (D), renamed (R)
27: 
28: After gathering, do a **secrets scan**: check untracked files for dangerous
29: patterns (`.env`, `*.key`, `*.pem`, `*.secret`, `credentials*`, `*token*`).
30: If any are found, **exclude them** from all commit groups and warn the user.
31: 
32: Also check for any **large binary files** (images, compiled assets, databases)
33: in untracked files — flag these for the user but don't auto-exclude.

75: ### Step 3 — Group by cohesion
76: 
77: Apply these grouping rules in order:
78: 
79: 1. **Implementation + its tests together**: If `foo.py` changed and
80:    `test_foo.py` also changed, they belong in the same commit.
81: 
82: 2. **Separate by commit type**: Don't mix these types in one commit:
83:    - `feat` — new functionality
84:    - `fix` — bug fixes
85:    - `refactor` — restructuring without behavior change
86:    - `test` — test-only changes (no implementation counterpart)
87:    - `docs` — documentation-only changes
88:    - `chore` — tooling, config, meta-files
89: 
90: 3. **Bulk mechanical changes together**: If many files have the same kind
91:    of change (e.g., all e2e tests updated for a rename, all example apps
92:    getting the same HTML change), group them into one commit even if they
93:    span multiple scopes.
94: 
95: 4. **New files vs modified files**: Untracked files that constitute a new
96:    feature should be grouped with related modified files. Standalone new
97:    files get their own commit.
98: 
99: ### Step 4 — Order by dependency
100: 
101: Sort commit groups in this order:
102: 1. Core framework changes (models, storage, utils, actors)
103: 2. Feature implementations (agents, api, ssr)
104: 3. Frontend changes (static/)
105: 4. Example app changes (example_*)
106: 5. Test-only changes
107: 6. Documentation
108: 7. Chore (meta-files, config, traces)
