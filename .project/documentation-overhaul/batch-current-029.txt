604: ## 7. Enhancement: SSR Pre-Loading — DONE
605: 
606: ### Problem
607: 
608: Two sequential network round-trips before any pixel renders:
609: 1. `GET /Product` (schema) → creates DynamicClass
610: 2. `GET /products` (data) → creates instances, renders
611: 
612: ### Solution: Inline Pre-Loading
613: 
614: Server-rendered pages can inline both schema and data as JSON:
615: 
616: ```html
617: <script type="application/json" data-ntx-schema="Product">
618:   {{ product_schema_json }}
619: </script>
620: <script type="application/json" data-ntx-data="products">
621:   {{ products_json }}
622: </script>
623: <ntx-list model="Product"></ntx-list>
624: ```
625: 
626: ### Implementation (completed)
627: 
628: Two private static helper methods added to `N3TX` class in `core/N3TX.js`:
629: 
630: - **`#consumePreloadedSchema(model)`** — Checks `document.querySelector('script[data-ntx-schema="ModelName"]')`. If found, parses JSON, feeds to `N3TX.SCHEMA()` directly, removes the script tag (one-shot consumption). Returns `true` if pre-loaded schema was found.
631: - **`#consumePreloadedData(tablename)`** — Checks `document.querySelector('script[data-ntx-data="tablename"]')`. If found, parses JSON, removes script tag, returns data array. Returns `null` if not found.
632: 
633: **Wired into three bootstrap paths:**
634: 
635: 1. `N3TX.attach()` — "Never seen" branch: tries `#consumePreloadedSchema(addr)` before sending SCHEMA TX
636: 2. `N3TX.ATTACH()` — "Never seen" branch: same pre-load check before network fetch
637: 3. `N3TX.SCHEMA()` — After creating DynamicClass: tries `#consumePreloadedData(tablename)` and calls `DC.READ(data)` directly instead of `DC.call('READ')` if found
638: 
639: **Queue-then-consume pattern**: Both `attach()` and `ATTACH()` set up the waiting queue *before* calling `#consumePreloadedSchema()`. This ensures that when `N3TX.SCHEMA()` runs synchronously and replays the queue, all pending callbacks/TXs are already queued.

665: ## 8. Enhancement: Adaptive Display Modes — DONE (Phase 2 + Phase 2.5)
666: 
667: ### Goal
668: 
669: A single component renders differently based on the space its parent allocates, not the screen size. This makes components truly context-aware — the same `<ntx-item>` works in a dashboard grid, a detail page, a sidebar, or an inline mention.
670: 
671: ### Size System
672: 
673: Abstract sizes (`xs`–`xl`) with semantic aliases for readability:
674: 
675: | Size | Alias | Breakpoint | NTTItem Default |
676: |------|-------|-----------|-----------------|
677: | `xs` | `pill` | 0px+ | Name badge only |
678: | `sm` | `list-item` | 200px+ | Compact row: name + 2–3 key fields |
679: | `md` | `card` | 400px+ | Full card: edit + form + methods |
680: | `lg` | `detail` | 600px+ | Detail (delegates to `md`; future: hidden fields) |
681: | `xl` | `page` | 800px+ | Page (delegates to `md`; future: metadata) |
682: 
683: ### Two Modes of Operation
684: 
685: **Auto mode (default):** ResizeObserver measures the component's content width and resolves to the largest matching breakpoint. No attribute needed.
686: 
687: **Forced mode:** Set the `display` attribute (or property) to lock a specific size:
688: 
689: ```html
690: <ntx-item display="xs"></ntx-item>    <!-- abstract name -->
691: <ntx-item display="pill"></ntx-item>  <!-- semantic alias -->
692: <ntx-item display="auto"></ntx-item>  <!-- back to auto -->
693: ```
694: 
695: When forced, the ResizeObserver still runs but its updates are ignored.
696: 
697: ### Implementation — Component.js (Phase 2)
698: 
699: Added to `core/Component.js` base class. Every component gets space-awareness for free.
700: 
701: **Static members:**
702: - `Component.SIZES = ['xs', 'sm', 'md', 'lg', 'xl']`
703: - `Component.ALIASES = {pill: 'xs', 'list-item': 'sm', card: 'md', detail: 'lg', page: 'xl'}`
704: - `Component.normalizeDisplay(value)` — resolves abstract or semantic name to abstract size, returns `null` for `'auto'` or unrecognized values
705: 
706: **Private state:**
707: - `#displayMode = 'md'` — current mode, initialized to `'md'`
708: - `#resizeObserver = null` — ResizeObserver instance
709: 
710: **Public API:**
711: 
712: - **`get displayBreakpoints()`** — Override in subclass to customize. Returns `{xl: 800, lg: 600, md: 400, sm: 200, xs: 0}`. Evaluated largest-first.
713: - **`get displayMode()`** — Returns the current abstract size string.
714: - **`get display()` / `set display(value)`** — Gets/sets the `display` attribute. Accepts abstract or semantic names.
715: - **`displayModeChanged(oldMode, newMode)`** — Hook called when mode changes. Default: re-renders if schema available.
716: 
717: **Lifecycle wiring:**
718: - `connectedCallback()` applies forced mode if `display` attribute is set, then starts ResizeObserver.
719: - `disconnectedCallback()` stops ResizeObserver, cleans up subscriptions.
720: - `attributeChangedCallback` for `'display'` normalizes value and updates `#displayMode`.
721: 
722: **ResizeObserver guard:**
723: ```js

725: if (Component.normalizeDisplay(this.getAttribute('display'))) return;

957:     if (def.minLength) attrs.push(`minlength="${def.minLength}"`);
958:     if (def.maxLength) attrs.push(`maxlength="${def.maxLength}"`);
959:     if (def.minimum != null) attrs.push(`min="${def.minimum}"`);
960:     if (def.exclusiveMinimum != null) attrs.push(`min="${def.exclusiveMinimum + 0.01}"`);
961:     if (def.maximum != null) attrs.push(`max="${def.maximum}"`);
962:     if (def.pattern) attrs.push(`pattern="${def.pattern}"`);
963:     if (schema.required?.includes(key)) attrs.push('required');
964: 
965:     html.push(`<input type="${inputType}" ${attrs.join(' ')} data-key="${key}" data-type="${type}" value="${value}">`);
966:   }
967: }
968: ```
969: 
970: The browser handles validation natively. No custom validation code needed for standard constraints.

992: })

996:

999: ### Frontend Implementation
1000: 
1001: **`utils/Permissions.js`** — Singleton module:
1002: - `permissions.init()` — Fetches `/auth/me` using the JWT from `localStorage['jwtToken']`. Non-blocking; deduplicates.
1003: - `permissions.user` — Current user object or null.
1004: - `permissions.role` — Current role string ('anonymous' if not logged in).
1005: - `permissions.canView(fieldDef)` — Checks `fieldDef.access.view` against user.
1006: - `permissions.canEdit(fieldDef)` — Checks `fieldDef.access.edit` against user.
1007: - `permissions.canAction(accessDict, action)` — Checks model-level `schema.access[action]` against user. Handles composite rules (or/and/not).
1008: 
1009: **Rule evaluation**:
1010: - `'anyone'` → always true
1011: - `'authenticated'` → true if logged in
1012: - `'owner'` → true if logged in (ownership enforced server-side)
1013: - Any other string → treated as role name, matched against `permissions.role`
1014: - Composite rules: `{op: 'or', rules: [...]}`, `{op: 'and', rules: [...]}`, `{op: 'not', rule: {...}}`
1015: 
1016: **Formidable integration** (`generators/form.js`):
1017: - `getForm()` filters out fields where `permissions.canView(def)` returns false
1018: - `getInput()` downgrades edit mode to display mode if `permissions.canEdit(def)` returns false
1019:

1021: - Edit button hidden if `permissions.canAction(schema.access, 'update')` returns false
1022: - `toggleMode()` blocked if user lacks update permission

1024: **Bootstrap**: `permissions.init()` called in `index.html` module script. Non-blocking — components degrade gracefully (show everything by default, apply restrictions once identity resolves).
