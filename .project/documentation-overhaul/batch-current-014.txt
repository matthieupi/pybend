527: 
528: **File**: `packages/n3tx-agents/src/n3tx_agents/static/components/ntx-stream-agent.js`
529: 
530: `NTTStreamAgent` extends `NTTStream` with rich agent output rendering — typed entries (thinking, tool calls, text), markdown rendering, and tool result cards. All agent-style streaming components extend `NTTStreamAgent` (or `NTTStream` directly for simpler cases).
531: 
532: **Component hierarchy:**
533: 
534: ```
535: Component → NTTMethod → NTTStream → NTTStreamAgent → (app subclasses)
536: ```
537: 
538: ```javascript
539: import { NTTStreamAgent } from './ntx-stream-agent.js';
540: 
541: class MyComponent extends NTTStreamAgent {
542:     // UPPERCASE methods = TX inbox handlers (actor convention)
543:     TEXT(data, meta)       { /* data.text */ }
544:     TOOL_CALL(data, meta)  { /* data.tool, data.args, data.call_id */ }
545:     TOOL_RESULT(data, meta){ /* data.tool, data.result */ }
546:     THINKING(data, meta)   { /* data.text */ }
547:     DONE(data, meta)       { /* data.answer, data.usage */ }
548: 
549:     // Lifecycle hooks
550:     STREAM_END(data)       { /* stream completed */ }
551:     STREAM_ERROR(err)      { /* stream failed */ }
552: }
553: ```
554: 
555: **Key methods:**
556: 
557: | Method | Purpose |
558: |--------|---------|
559: | `prerender()` | Structural DOM created before schema loads. Never wiped by render(). |
560: | `callMethod()` | Start stream via TX with `meta: {stream: true, req: reqId}`. |
561: | `cancel()` | Client-side cancel: sets `#cancelled` flag, sends `STREAM_CANCEL` TX. |
562: 
563: **How dispatch works:**
564: 
565: 1. `callMethod()` sends TX with `meta: {stream: true}` via the Actor system.
566: 2. Backend sends stream chunks as TX messages.
567: 3. `NTTStream.STREAM()` handler receives chunks, skips if `#cancelled`.
568: 4. Dispatches to UPPERCASE handlers: `THINKING()`, `TOOL_CALL()`, `TEXT()`, `DONE()`, etc.
569: 
570: **UPPERCASE convention**: All methods that handle TX messages are UPPERCASE. This mirrors the backend actor handler pattern and visually separates inbox handlers from internal component logic (lowercase/camelCase).

609: ## Message Flow
610: 
611: Complete lifecycle of an agent tool call:
612: 
613: ```
614: 1. POST /agents/1/run {"task": "Scan grants.gov for new grants"}
615:         |
616: 2. AgentActor(id=1).run(task)
617:    --> calls self.agent_run(self.prompt, self.tools, task)
618:         |
619: 3. AgentMixin.run():
620:    a. Resolves LLM from config cascade
621:    b. discover_tools(["grants", "web_tools"], matrix)
622:       --> Gets schema.methods from each actor
623:       --> Builds ToolSpec list: grants_create, grants_list, ...,
624:                                 web_tools_scrape, web_tools_extract
625:    c. Creates pydantic_ai.Agent(llm, system_prompt, tools=[...])
626:    d. Runs ai_agent.run(task, deps=AgentDeps(user, agent_addr))
627:         |
628: 4. Pydantic AI loop (internal):
629:    a. Sends messages + tool specs to LLM
630:    b. LLM responds: tool_use("web_tools_scrape", {url: "https://..."})
631:    c. Pydantic AI validates args, calls generated tool function
632:    d. Tool function creates TX(name='scrape', target='web_tools', data={...})
633:    e. adapter.request(tx) --> Matrix routes --> WebTools.handler()
634:       --> scrape() method executes
635:       --> Response TX returns via Future correlation
636:    f. Tool result (JSON string) sent back to LLM
637:    g. LLM calls more tools or produces final answer
638:         |
639: 5. agent_run() returns {answer, usage, messages}
640: 6. Transient adapter cleaned up (finally block)
641: 7. run() returns JSON to HTTP response
642: ```

1: # Standard CRUD Endpoints
2: 
3: This document describes the auto-generated CRUD endpoints available for every storable model in N3TX.
4: 
5: All CRUD route handlers call `.model_response()`, which injects `$schema` and `$id` metadata into every response. This runs the composable dump pipeline (`proto_dump`), making each response self-describing.
6: 
7: ## Endpoint Pattern
8: 
9: For a model with `__tablename__ = 'users'`, N3TX generates:
10: 
11: | Operation | Method | Path | Description |
12: |-----------|--------|------|-------------|
13: | Schema | GET | `/User` | Get model JSON schema |
14: | Class-name list mirror | GET | `/User/_` | Explicit collection mirror of `/users` |
15: | Class-name create mirror | POST | `/User` | Create mirror of `/users` |
16: | Class-name read mirror | GET | `/User/{id}` | Read mirror of `/users/{id}` |
17: | Class-name update mirror | PUT | `/User/{id}` | Update mirror of `/users/{id}` |
18: | Class-name delete mirror | DELETE | `/User/{id}` | Delete mirror of `/users/{id}` |
19: | Create | POST | `/users` | Create new user |
20: | List | GET | `/users` | Get all users |
21: | Read | GET | `/users/{id}` | Get specific user |
22: | Update | PUT | `/users/{id}` | Update user |
23: | Delete | DELETE | `/users/{id}` | Delete user |
24: 
25: **Note**: `GET /{ClassName}` remains the schema endpoint. Class-name collection
26: reads use the explicit `_` marker (`GET /{ClassName}/_`), and class-name writes
27: reuse the same handlers or actor TX contracts as table-name routes. Literal
28: `@expose_route` methods may also have class-name mirrors; there is no generic
29: method catch-all.

342: users.forEach(user => {
