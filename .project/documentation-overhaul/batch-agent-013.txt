6: 
7: # N3TX Actors
8: 
9: Actors are the reusable compute and message boundary in N3TX.
10: 
11: ## Core concept
12: 
13: ```text
14: TX(name, source, target, data, meta)
15:    -> Matrix routes by target address
16:    -> Actor / ActorModel handler
17:    -> reply/error/stream TX
18: ```
19: 
20: `ActorModel` combines model/schema/storage with actor messaging.
21: 
22: ## Use ActorModel for app capabilities
23: 
24: ```python
25: from n3tx_actors.models.actor_model import ActorModel
26: from n3tx_core.utils.decorators import expose_route
27: 
28: 
29: class Calculator(ActorModel):
30:     __tablename__ = 'calculators'
31:     __storable__ = False
32: 
33:     @expose_route('/add', methods=['POST'])
34:     def add(self, a: float, b: float) -> dict:
35:         return {'result': a + b}
36: ```
37: 
38: This capability can be used by UI, agents, MCP/tools, workflows, or other actors.
39: 
40: ## Addressing
41: 
42: ```text
43: Class actor:    products
44: Instance actor: products/1
45: ```
46: 
47: For storable `ActorModel`, CRUD TX names include `schema`, `create`, `get`, `list`, `update`, `delete`.
48: 
49: ## When to use each shape
50: 
51: | Shape | Use when |
52: |---|---|
53: | `ActorModel` storable | Entity plus actor behavior |
54: | `ActorModel` non-storable | Tool/service capability with schema-discoverable methods |
55: | Plain `Actor` | Low-level actor without model/schema/storage needs |
56: | `ActorProxy` | Wrap third-party object as actor |
57: | `RemoteRef` | Explicit async handle for a remote `n3tx://...` model identity |
58: | `NetworkAdapter` | Protocol bridge or external network boundary |
59: 
60: ## Distributed actor refs
61: 
62: Canonical distributed refs use class-name identity:
63: 
64: ```text
65: n3tx://<service>/<ClassName>/<id>
66: ```
67: 
68: `RemoteMatrix` routes those refs through existing remote class-name REST routes:
69: 
70: ```text
71: TX(name='get', target='n3tx://storage/File/12')     -> GET  /File/12
72: TX(name='process', target='n3tx://storage/File/12') -> POST /File/12/process
73: TX(name='generate', target='n3tx://compute/Job/12', meta={'stream': True})
74:   -> RemoteMatrix.stream() -> remote generated SSE route -> TX chunks
75: ```
76: 
77: For distributed streaming, keep the capability as an exposed actor/model method
78: with `@expose_route(..., stream=True)`. `RemoteMatrix.stream()` reads the remote
79: schema method route before falling back to the legacy method-name URL shape, so
80: custom decorator routes remain the source of truth.
81: 
82: For explicit Python calls, use `ActorModel.ref()` rather than hidden network IO
83: in normal field access:
84: 
85: ```python
86: artifact = Artifact.ref('n3tx://storage/Artifact/42', matrix=matrix)
87: data = await artifact.get()
88: result = await artifact.call('process', mode='fast')
89: ```
90: 
91: ## Lifecycle events
92: 
93: `ActorModel` publishes lifecycle TX after create/update/delete. Subscribers can power federation, audit, agents, or realtime bridges.
94: 
95: ## Guardrails
96: 
97: - Put reusable compute in actors, not hidden helpers.
98: - Do not route internal work through plain HTTP.
99: - Do not hide remote network IO behind ordinary model field access; use populate or `RemoteRef`.
100: - Do not bypass `ActorModel` CRUD when actor routing is the app architecture.
101: - Do not make the actor system depend on UI/HTML concerns.
102: 
103: ## Verification
104: 
105: - Actor is registered with Matrix under the expected address.
106: - TX reaches the correct handler.
107: - Errors return error TXs.
108: - Exposed methods appear in schema and can be discovered as tools.
109: - Remote refs route through Matrix adapter fallback and return TX replies/errors.
110: - Remote streaming refs yield TX chunks/errors/end through `RemoteMatrix.stream()`.
111: 
112: ## Source-reading policy
113: 
114: Inspect framework source only when docs/skills are insufficient, do not cover the intended implementation, or observed behavior contradicts docs. Update/propose docs when gaps are found.

77: ```

6: 
7: # N3TX Authorization
8: 
9: Authorization is backend-owned and schema-exposed. The frontend adapts; it is not the source of truth.
10: 
11: ## Built-in rules
12: 
13: ```python
14: from n3tx_core.authorize import ANYONE, AUTHENTICATED, OWNER, ROLE, Where
15: ```
16: 
17: Rules compose:
18: 
19: ```python
20: OWNER | ROLE('admin')
21: OWNER & Where(status='draft')
22: ~ROLE('banned')
23: ```
24: 
25: ## Model access
26: 
27: ```python
28: class Product(ActorModel):
29:     __owner_field__ = 'user_owner'
30:     __access__ = {
31:         'read': ANYONE,
32:         'create': AUTHENTICATED,
33:         'update': OWNER | ROLE('admin'),
34:         'delete': ROLE('admin'),
35:     }
36: ```
37: 
38: If `__access__` is omitted, the schema exposes the authenticated wildcard fallback.
39: 
40: ## Method access
41: 
42: ```python
43: @expose_route('/publish', methods=['POST'], access=OWNER | ROLE('admin'))
44: def publish(self) -> dict:
45:     return {'status': 'published'}
46: ```
47: 
48: ## User injection
49: 
50: Custom methods can receive authenticated user context by declaring `user`:
51: 
52: ```python
53: @expose_route('/comment', methods=['POST'], access=AUTHENTICATED)
54: def comment(self, text: str, user: User = None) -> dict:
55:     return {'author': user.id if user else None, 'text': text}
56: ```
57: 
58: The `user` parameter is injected by the route layer and is not read from request body.
59: 
60: ## Protected fields
61: 
62: ```python
63: class Comment(ActorModel):
64:     __owner_field__ = 'user_owner'
65:     __protected_fields__ = {'user_owner'}
66:     user_owner: int | None = None
67: ```
68: 
69: Protected fields are hidden in edit forms, auto-injected on create, and stripped on update.
70: 
71: ## Actor routing auth
72: 
73: In Level 3, auth is two-tier:
74: 
75: ```text
76: NetworkAPI.request interceptor
77:    -> identity/role gate and list SQL filter
78: Matrix -> ActorModel.handler_crud
79:    -> resource-aware OWNER check
80: ```
81: 
82: ## Service-to-service auth for distributed refs
83: 
84: `RemoteMatrix` sends trusted backend identity and optional user continuity:
85: 
86: ```text
87: Authorization: Bearer <remote-or-service-token>
88: X-N3TX-Service: <local-service-name>
89: X-N3TX-User: <json-user-context>  # optional
90: ```
91: 
92: The receiving backend accepts the request only when the bearer token matches its
93: configured `SERVICE_TOKEN`. If `X-N3TX-User` is present, it must be a JSON object
94: and becomes `request.state.user`, so generated routes and ActorModel ABAC remain
95: the authoritative authorization path. Service auth establishes backend trust; it
96: does not replace model `__access__` or method `access=` rules.
97: 
98: ## Guardrails
99: 
100: - Do not rely on UI-only auth.
101: - Do not duplicate access logic in frontend code as source of truth.
102: - Do not bypass `__access__` with custom routes.
103: - Do not trust request body for protected ownership fields.
104: - Do not treat service tokens as user permissions; forward user context and let ABAC evaluate it.
105: 
106: ## Verification
107: 
108: - Unauthorized create/update/delete fails.
109: - OWNER succeeds for owned records and fails for others.
110: - Admin/role rules behave as expected.
111: - Schema `access` section reflects rules for frontend adaptation.
112: - Service-token remote calls reject invalid tokens and preserve forwarded user context.

56: | App bootstrap/static/import ordering | `n3tx-app-bootstrap` |
57: | External APIs/webhooks/scraping/cloud services | `n3tx-external-integrations` |
58: 
59: ## Backend feature shape
60: 
61: ```python
62: class Product(ActorModel):
63:     __tablename__ = 'products'
64:     __storable__ = True
65:     __owner_field__ = 'user_owner'
66:     __access__ = {
67:         'read': ANYONE,
68:         'create': AUTHENTICATED,
69:         'update': OWNER | ROLE('admin'),
70:         'delete': ROLE('admin'),
71:     }
72:     __ui__ = {'field_order': ['name', 'price'], 'renderer': {'item': 'ntx-item'}}
73: 
74:     name: str
75:     price: float
76:     user_owner: int | None = None
77: 
78:     @expose_route('/publish', methods=['POST'], access=OWNER | ROLE('admin'))
79:     def publish(self, user=None) -> dict:
80:         return {'status': 'published'}
81: ```
82: 
83: ## Relationships
84: 
85: Prefer field-declared relationships over manual plumbing:
86: 
87: ```python
88: class Product(ActorModel):
89:     __tablename__ = 'products'
90:     __storable__ = True
91:     comments: ListRef['Comment'] = []       # parent-scoped children
92:     tags: ManyToMany[Tag] = []              # shared independent entities
93: ```
94: 
95: `ListRef[T]` expresses parent/child nesting. `ManyToMany[T]` expresses shared
96: membership and is discovered by `create_app()` / `N3TXApp`, which generates the
97: link model/table during bootstrap.
98: 
99: ## Distributed refs
100: 
101: Use `Ref[T]` for a single local/distributed model identity and `list[Ref[T]]` for
102: JSON-backed pointer arrays. Keep `ListRef[T]` for local owned relationships.
103: 
104: ```python
105: class Job(ActorModel):
106:     __tablename__ = 'jobs'
107:     __storable__ = True
108: 
109:     owner: Ref[User] | None = None
110:     files: list[Ref[File]] = []
111:     comments: ListRef[Comment] = []
112: ```
113: 
114: Configured remote HTTP refs canonicalize to `n3tx://service/Class/id`. Actor
115: routing with `remotes={...}` registers `RemoteMatrix` and injects a
116: `MatrixReferenceResolver` so populate can best-effort resolve remote refs without
117: making `n3tx-core` import actors.
118: 
119: ## Files
120: 
121: For detailed file behavior, load `n3tx-files`. This backend index only names the
122: boundary: files are first-class metadata records and bytes live behind a
123: `FileStore` provider.
124: 
125: ```python
126: from n3tx_files import File, LocalFileStore, configure_file_store
127: 
128: configure_file_store(LocalFileStore('./file-blobs'))
129: app = create_app(models=[File, Product], storage='sqlite:///app.db')
130: ```
