395: ### Streaming Infrastructure
396: For the full streaming mechanism, see `packages/n3tx-actors/docs/network-adapters.md` (adapter streaming) and `packages/n3tx-core/docs/app-bootstrap.md` (route-level streaming).
397: 
398: #### Defining a Streaming Method
399: ```python
400: @expose_route('/generate', methods=['POST'], stream=True, access=AUTHENTICATED)
401: async def generate(self, prompt: str = ''):
402:     for i in range(10):
403:         await asyncio.sleep(0.1)
404:         yield {'chunk': f'Processing step {i}'}
405: ```
406: 
407: #### Schema-Declared Stream Events (`events=`)
408: 
409: Streaming methods can declare their event vocabulary via the `events=` parameter. Event types are non-storable `ProtoModel` subclasses — pure Pydantic models for validation and JSON Schema generation:
410: 
411: ```python
412: class TextChunk(ProtoModel):
413:     text: str = Field(default='')
414: 
415: class DoneChunk(ProtoModel):
416:     answer: str = Field(default='')
417:     usage: dict = Field(default={})
418: 
419: @expose_route('/agentic_stream', methods=['POST'], stream=True,
420:               events={'text': TextChunk, 'done': DoneChunk})
421: async def agentic_stream(self, task: str, **kwargs):
422:     yield {'name': 'text', 'data': {'text': 'hello'}, 'meta': {'stream': True, 'seq': 0}}
423: ```
424: 
425: The `methods` stage in `proto_model.py` serializes `events` into the method schema:
426: 
427: ```json
428: {
429:   "methods": {
430:     "agentic_stream": {
431:       "stream": true,
432:       "events": {
433:         "text": {"type": "object", "properties": {"text": {"type": "string"}}},
434:         "done": {"type": "object", "properties": {"answer": {...}, "usage": {...}}}
435:       }
436:     }
437:   }
438: }
439: ```
440: 
441: The `n3tx-agents` package ships five built-in event models in `actor.py`: `TextChunk`, `ToolCallEvent`, `ToolResultEvent`, `ThinkingChunk`, `DoneChunk`. These are used by `AgentActor.agentic_stream()`. Custom streaming methods can define their own event models.
442: 
443: #### TX Stream Protocol
444: TX uses `meta` fields for stream correlation:
445: 
446: | Message | `meta` fields |
447: |---------|--------------|
448: | Chunk | `req: uuid`, `stream: True`, `seq: N` |
449: | End | `req: uuid`, `stream: True`, `stream_end: True`, `seq: N` |
450: | Error | Existing `tx.error()` — `is_error` terminates the stream |
451: 
452: Helper methods: `tx.stream_chunk(data, seq)`, `tx.stream_end(data, seq)`.
453: 
454: #### SSE Wire Format
455: ```
456: event: chunk|done|error
457: data: {json}\n\n
458: ```
459: Response headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`.
