27:      |                         methods → defs → access → widget → ui → [viewable] → [agent] → metadata)
28:      |                         [ ] = registered by external packages at import time

30:      |                         schema_url → instance_url → populate

32:      |                         loops _mixin_registry for external mixins (ViewableMixin, AgentMixin)
33:      +-- register_mixin()      Module-level API — external packages register mixins at import time
34:      |
35:      v

37: (n3tx-actors)        in actor messaging. CRUD via handler_crud(), lifecycle events,
38:                       same schema/storage as ProtoModel.
39:      |
40:      v
41: register_model()     Registers model with storage backend
42:      |
43:      v
44: register_routes()    Auto-generates CRUD routes from registered models (routes_fastapi.py)
45:      |
46:      v

131: ### BaseUser Pattern
132: ```python
133: from n3tx_core.models.base_user import BaseUser
134: 
135: class User(BaseUser):
136:     __tablename__ = 'users'
137:     __abstract__ = False
138:     image: Optional[str] = Field(default=None)
139: ```
140: `BaseUser` provides: `name`, `email`, `role`, `password_hash`, plus `login()` and `register_user()` endpoints. The method was renamed from `register()` to `register_user()` to avoid MRO collision with `Actor.register()`.
141: 
142: ### Local Model Collections
143: ```python
144: class Product(ProtoModel):
145:     comments: list[Comment] = Field(default=[])
146: ```
147: 
148: `list[T]` stores an ordered JSON list of local child ids on the parent row and
149: hydrates those ids into self-describing child objects in responses. Use custom
150: methods such as `Product.comment(...)` for domain-specific append/toggle actions.
151: For shared relationships, prefer an explicit link model; `ManyToMany[T]` remains
152: a legacy helper for existing shared-link use cases.
153: 
154: ### Custom Method Return Types
155: `@expose_route` methods may return any import-resolvable model type, including a
156: different `ProtoModel` than the route owner. With `from __future__ import
157: annotations`, route registration resolves return annotations through
158: `typing.get_type_hints()` before passing them to FastAPI's `response_model`, so
159: patterns such as `Product.comment(...) -> Comment` remain valid and validated.
160: 
161: ### Custom Method Scope
162: 
163: `@expose_route` method scope is descriptor-aware and published in schema as both
164: `scope` and `requires_instance`. Route generation, actor dispatch, tool
165: discovery, and remote streaming should use `requires_instance` for routing
166: decisions:
167: 
168: | Python declaration | Schema `scope` | `requires_instance` | Route shape |
169: |---|---|---:|---|
170: | `def action(self, ...)` | `instancemethod` | `true` | `POST /{ClassName}/{id}/{route}` |
171: | `@classmethod def action(cls, ...)` | `classmethod` | `false` | `POST /{ClassName}/{route}` |
172: | `@staticmethod def action(...)` | `staticmethod` | `false` | `POST /{ClassName}/{route}` |
173: | `def action(...)` with no `self`/`cls` | `actormethod` | `false` | `POST /{ClassName}/{route}` |
174: 
175: For decorator order, prefer the normal Python descriptor shape:
176: 
177: ```python
178: @staticmethod
179: @expose_route('/upload-to-splat', methods=['POST'], stream=True)
180: async def upload_to_splat(...):
181:     ...
182: 
183: @classmethod
184: @expose_route('/rebuild', methods=['POST'])
185: def rebuild(cls):
186:     ...
187: ```
188: 
189: The schema-declared route path is authoritative for distributed calls. For
190: example, `RemoteMatrix.stream()` resolves `POST /ComputePipeline/upload-to-splat`
191: from schema metadata instead of synthesizing `/ComputePipeline/0/upload_to_splat`
192: when `requires_instance` is false.
193: 
194: ### API Response Format
195: All entity responses include `$schema` (schema URL) and `$id` (instance URL), injected by `model_response()` via the dump pipeline.
196: 
197: ### Route Grammar and Hypermedia View Entrypoints
198: 
199: N3TX exposes an additive dual route grammar. Table-name routes remain the
200: compatibility JSON API; class-name routes provide schema, read mirrors, and
201: HTML/view entrypoints.
202: 
203: | Route | Layer | Response | Notes |
204: |---|---|---|---|
205: | `GET /{ClassName}` | schema/type | JSON Schema | Existing schema endpoint |
206: | `GET /{tablename}` | data API | JSON list | Existing table-name API |
207: | `POST /{tablename}` | data API | JSON entity | Existing create route |
208: | `GET /{tablename}/{id:int}` | data API | JSON entity | Existing canonical read route |
209: | `PUT /{tablename}/{id:int}` | data API | JSON entity | Existing update route |
210: | `DELETE /{tablename}/{id:int}` | data API | JSON status/payload | Existing delete route |
211: | `POST /{tablename}/{id:int}/{method}` | method API | JSON/SSE | Existing `@expose_route` instance methods |
212: | `GET /{ClassName}/_` | class-name mirror | JSON list | Explicit `_` collection marker |
213: | `POST /{ClassName}` | class-name mirror | JSON entity | Create mirror; `GET /{ClassName}` stays schema |
214: | `GET /{ClassName}/{id:int}` | class-name mirror | JSON entity | Read mirror of table-name read |
215: | `PUT /{ClassName}/{id:int}` | class-name mirror | JSON entity | Update mirror |
216: | `DELETE /{ClassName}/{id:int}` | class-name mirror | JSON status/payload | Delete mirror |
217: | `POST /{ClassName}/{id:int}/{method}` | class-name mirror | JSON/SSE | Literal `@expose_route` method mirror |
218: | `GET /{ClassName}/@` | view/html | HTML | Collection default view shell |
219: | `GET /{ClassName}/@{view}` | view/html | HTML | Collection named view shell |
220: | `GET /{ClassName}/{id:int}/@` | view/html | HTML | Member default view shell |
221: | `GET /{ClassName}/{id:int}/@{view}` | view/html | HTML | Member named view shell |
222: 
223: The class-name JSON mirrors intentionally reuse the same handlers as the
224: table-name routes in direct FastAPI routing. `GET /{ClassName}` remains schema;
225: `GET /{ClassName}/_` is the explicit JSON collection marker. Actor routing
226: dispatches equivalent TXs to the table-name actor address. In both modes, auth,
227: population query parameters, missing-record behavior, and serialization stay
228: aligned with the table-name route.
229: 
230: Response identity is class-name based: a response fetched through either
231: `GET /products/1` or `GET /Product/1` has `$schema` ending in `/Product` and
232: `$id` ending in `/Product/1`. Method mirrors are registered only for literal
233: `@expose_route` declarations; there is no generic class-name method catch-all.
234: 
235: #### Partial update contract
236: 
237: Generated `PUT /{tablename}/{id}` and `PUT /{ClassName}/{id}` handlers in direct
238: and actor routing preserve the supplied JSON patch. `StorableMixin.update()`
239: merges it with the current entity, validates the complete result through the
240: original model, and sends only supplied fields to storage. This is the same
241: contract used by direct backend calls and raw TX updates:
242: 
243: ```python
244: Product.update(product.id, {'name': 'Renamed'})  # patch; other fields unchanged
245: TX(name='update', target='products', data={'id': product.id, 'name': 'Renamed'})
246: ```
247: 
248: Omitted fields remain unchanged. Supplied collections are replaced as a whole
249: and writes are last-write-wins; use domain-specific `@expose_route` methods for
250: append/remove/toggle operations where concurrent mutation matters.
251: Canonical details: `docs/API_CRUD_ENDPOINTS.md#update-resource` and
252: `packages/n3tx-core/docs/storage.md#update-boundary-contract`.
253: 
254: Local owned collections are declared as `list[T]` fields on the parent. SQLite
255: stores an ordered JSON list of child ids and hydrates those ids into
256: self-describing child objects on read. Public child identity remains flat and
257: class-name based, e.g. `$id=/Comment/2`; nested route identity is not a storage
258: primitive. If a parent has multiple relationships to the same child class, for
259: example `comments: list[Comment]` and `reviews: list[Comment]`, the relationship
260: field name remains local schema/UI metadata on the parent while the child model

271: ### Authorization (ABAC)
272: ```python
273: from n3tx_core.authorize import ANYONE, AUTHENTICATED, OWNER, ROLE, Where
274: 
275: class Product(ProtoModel):
276:     __owner_field__ = 'user_owner'
277:     __access__ = {
278:         'read':   ANYONE,
279:         'create': AUTHENTICATED,
280:         'update': OWNER | ROLE('admin'),
281:         'delete': ROLE('admin'),
282:     }
283: ```
284: Rules compose with `|` (OR), `&` (AND), `~` (NOT). See `packages/n3tx-core/docs/authorization.md` for full details.

286: ### Self-Referential Nesting
287: ```python
288: class Comment(ProtoModel):
289:     parent_id: Optional[Ref['self']] = Field(default=None)
290: ```
291: `Ref['self']` emits `{"type": "selfref"}` in JSON Schema. Stored as nullable `INTEGER` column.

293: ### Distributed Ref Configuration
294: 
295: Distributed backend-to-backend reference helpers read process config by default:
296: 
297: ```text
298: N3TX_SERVICE_NAME=api
299: N3TX_SERVICE_TOKEN=...
300: N3TX_REMOTES={"storage":{"url":"http://storage:7100","token":"..."}}
301: ```
302: 
303: Apps can override deployment defaults during bootstrap:
304: 
305: ```python
306: app = create_app(
307:     models=[Job],
308:     routing='actor',
309:     remotes={'storage': {'url': 'http://storage:7100', 'token': '...'}},
310:     service_name='api',
311:     service_token='...',
312: )
313: ```
314: 
315: `Ref[T]` accepts local ids, local class-name paths such as `/File/12`, current
316: API URLs, configured remote HTTP URLs, and canonical `n3tx://service/Class/id`
317: refs. Configured remote HTTP refs canonicalize to `n3tx://...`; unconfigured
318: HTTP(S) URLs are external links, not Matrix refs.
319: 
320: Remote dereference/populate is opt-in. `SQLiteStorage(reference_resolver=None)`
321: preserves local-only behavior. Actor routing with configured `remotes` registers
322: `RemoteMatrix` and injects `MatrixReferenceResolver` into compatible storage
323: backends. For explicit Python calls to a remote model identity, use:
324: 
325: ```python
326: artifact = Artifact.ref('n3tx://storage/Artifact/42')
327: result = await artifact.call('process', mode='fast')
328: ```
329: 
330: `RemoteMatrix` sends `Authorization: Bearer <token>`, `X-N3TX-Service`, and
331: optional `X-N3TX-User` headers. A receiving N3TX backend accepts service calls
332: when the bearer token matches its configured `SERVICE_TOKEN`; forwarded user JSON
333: is installed as `request.state.user` so existing route and ActorModel ABAC
334: behavior remains authoritative. Remote HTTP `$id` values are canonicalized back
335: to `n3tx://service/Class/id` before returning through Matrix/populate.

337: ### JSON Fields (dict/list in SQLite)
338: The storage layer transparently handles `dict`, `Dict[...]`, `list`, primitive
339: typed list fields, local owned `list[T]` id arrays, and `list[Ref[T]]` pointer
340: arrays as JSON TEXT columns. Write paths serialize with `json.dumps(value,
341: default=str)`; read paths deserialize with `json.loads()` before Pydantic model
342: construction and hydrate local `list[T]` ids into objects.
343: 
344: Use JSON fields for parent-owned embedded data such as metadata, settings,
345: agent constraints, primitive tags, external payload fragments, distributed
346: pointer arrays, and local owned relationship id lists. Model children that need
347: independent auth, lifecycle, or row-level updates as first-class storable models
348: and point to them from parent `list[T]` fields.
349: 
350: Full guide: `docs/JSON_FIELDS.md`. Package mechanism reference:
351: `packages/n3tx-core/docs/storage.md`.

368: ### NetworkAdapter Pattern
369: ALL external protocol interaction flows through a `NetworkAdapter(Actor)`. Each adapter translates between an external protocol and TX messages. See `packages/n3tx-actors/docs/network-adapters.md`.
370:

372: from n3tx_actors.api.network_mcp import NetworkMCP, create_mcp_routes

376: matrix.register(mcp)
377: app.include_router(create_mcp_routes(mcp))
378: ```
