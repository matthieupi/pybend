6: 
7: # N3TX Frontend
8: 
9: The N3TX frontend is schema-driven. It should adapt to backend contracts instead of re-declaring them.
10: 
11: If the task is focused, prefer the specialist skill directly. Use
12: `n3tx-skill-routing` when skill choice is ambiguous.
13: 
14: ## Frontend mental model
15: 
16: ```text
17: GET /{ClassName} schema
18:    -> NTT.SCHEMA()
19:    -> DynamicClass via prototype()
20:    -> components render using schema.properties/ui/access/methods/$defs
21: ```
22: 
23: The browser receives a complete model contract. Use that contract.
24: 
25: ## Component layers
26: 
27: | Layer | Purpose |
28: |---|---|
29: | `n3tx-core/static/core` | Actor/TX/Matrix, entity registry, transport, abstract component bridge |
30: | `n3tx-ui/static/components` | Visual Web Components such as `ntx-list`, `ntx-item`, `ntx-method`, `ntx-stream` |
31: | `n3tx-ui/static/generators/form.js` | Formidable schema-driven forms |
32: | `n3tx-ui/static/widgets` | Field widgets selected by schema |
33: | `n3tx-agents/static/components` | Agent UI such as `ntx-chat`, `ntx-agent-live`, `ntx-stream-agent` |
34: 
35: ## Frontend route grammar
36: 
37: ```text
38: #Product              legacy/default collection
39: #Product/@            collection default view
40: #Product/@table       collection named view
41: #Product/1            legacy/default detail
42: #Product/1/@          member default view
43: #Product/1/@chat      member named view
44: #Product/1/run        method/action route
45: #Product/1/@run       view named run, not a method
46: #@profile             app-level route
47: ```
48: 
49: The `@` segment always means view/presentation, never data or method invocation.
50: 
51: Theme, shell, topbar, sidebar, profile routes, route-template mounting, icons,
52: and token contracts are frontend concerns too. Treat `FRONTEND.md` and
53: `packages/n3tx-ui/docs/styling.md` as the canonical references for those areas.

56: 
57: | Schema section | Frontend use |
58: |---|---|
59: | `properties` | fields, validation hints, form inputs |
60: | `properties[f].ui.widget` | widget selection |
61: | `properties[f].ui.display` | hide/show fields |
62: | `properties[f].access` | field-level visibility |
63: | `ui.field_order` | form order |
64: | `ui.groups` | fieldsets |
65: | `ui.renderer` | custom component tags for views |
66: | `access` | edit/delete/action visibility |

6: 
7: # N3TX JSON Fields
8: 
9: Use this skill when working with `dict`, `list`, typed list, or nested payload
10: fields on N3TX models.
11: 
12: Authoritative guide: `docs/JSON_FIELDS.md`.
13: 
14: ## Mental model
15: 
16: ```text
17: Model annotation
18:   -> get_json_fields(model_class)
19:   -> SQLite TEXT column
20:   -> json.dumps(value, default=str) on write
21:   -> json.loads(value) on read
22:   -> Pydantic validation / model instance
23: ```
24: 
25: JSON fields are embedded data owned by the parent row. They are not independent
26: resources.
27: 
28: ## Supported shapes
29: 
30: Stored as JSON TEXT:
31: 
32: ```python
33: metadata: dict = {}
34: config: Optional[dict] = None
35: tags: list[str] = []
36: scores: list[int] = []
37: payloads: list = []
38: ```
39: 
40: Not JSON fields:
41: 
42: ```python
43: comments: ListRef[Comment] = []   # relationship / join table
44: children: list[Comment] = []      # relationship-style collection
45: ```
46: 
47: ## Use JSON fields for
48: 
49: - metadata blobs
50: - agent constraints/config
51: - primitive tag arrays
52: - external API payload fragments
53: - cache-like embedded data
54: - settings that do not need independent identity
55: 
56: ## Use relationships for
57: 
58: - comments, likes, child resources
59: - anything with owner/auth requirements
60: - values needing `$id`, routes, lifecycle events, or pagination
61: - data that must be queried, updated, or rendered independently
62:

75:

5: ---
6: 
7: # N3TX Methods and Routes
8: 
9: Custom behavior belongs in model/actor methods exposed with `@expose_route`.
10: 
11: ## Basic method
12: 
13: ```python
14: from n3tx_core.utils.decorators import expose_route
15: 
16: class Product(ActorModel):
17:     __tablename__ = 'products'
18:     __storable__ = True
19: 
20:     @expose_route('/discount', methods=['POST'])
21:     def discount(self, percent: float) -> dict:
22:         return {'new_price': self.price * (1 - percent / 100)}
23: ```
24: 
25: Routes generated:
26: 
27: ```text
28: POST /products/{id}/discount
29: POST /Product/{id}/discount
30: ```
31: 
32: The method also appears in schema under `methods.discount`, allowing frontend buttons and agent tool discovery.
33: 
34: ## Method parameters
35: 
36: - Parameters come from function signatures.
37: - Type hints become schema.
38: - `user` is injected by auth layer and omitted from request body/tool args.
39: - Return annotations can describe response models.
40: 
41: ## Toggle method pattern
42: 
43: ```python
44: @expose_route('/favorite', methods=['POST'], access=AUTHENTICATED)
45: def favorite(self, user: User = None) -> dict:
46:     return {'action': 'favorited', '_field': 'favorites', 'id': 123, 'user': user.id}
47: ```
48: 
49: Toggle endpoints may accept empty bodies. Return structured payloads so the frontend can update local collections.
50: 
51: ## Route grammar
52: 
53: ```text
54: /{tablename}/...       JSON data API and custom methods
55: /{ClassName}           schema endpoint
56: /{ClassName}/_         JSON collection mirror
57: /{ClassName}/{id}      JSON instance mirror
58: /{ClassName}/{id}/{method} literal method mirror
59: /{ClassName}/@...      HTML/view shell entrypoints
60: ```
61: 
62: `@` is reserved for views and never invokes methods.
63: 
64: ## Guardrails
65: 
66: - Do not add custom FastAPI routes for normal model actions.
67: - Do not create generic catch-all method routes.
68: - Do not manually parse request bodies when signatures can declare types.
69: - Do not make methods call internal HTTP endpoints; call model/actor boundaries directly or use TX where appropriate.
70: 
71: ## Verification
72: 
73: - Schema method includes route, methods, parameters, return, access, stream/events when applicable.
74: - Table-name and class-name method mirrors behave consistently.
75: - Frontend renders method via `ntx-method`/`ntx-stream` when schema says so.
76: - Agent tool discovery can see the method if actor/model is in tools list.
77: 
78: ## Source-reading policy
79: 
80: Inspect framework source only when docs/skills are insufficient, do not cover the intended implementation, or observed behavior contradicts docs. Update/propose docs when gaps are found.

6: 
7: # N3TX Models
8: 
9: Models are the source of truth for the whole stack.
10: 
11: ## Choose a base class
12: 
13: | Base | Use when |
14: |---|---|
15: | `ProtoModel` | Data/schema/storage without actor capabilities |
16: | `ActorModel` | Model should receive TX, expose tools, participate in agents/networking/lifecycle |
17: | `BaseUser` | User model with login/register/password hashing |
18: | `AgentActor` | Dynamic persisted agent instances |
19: 
20: Default for new app entities: **`ActorModel`** if the app may use agents, workflows, actor routing, or reusable capabilities.
21: 
22: ## Canonical model
23: 
24: ```python
25: from pydantic import Field
26: 
27: from n3tx_actors.models.actor_model import ActorModel
28: from n3tx_core.authorize import ANYONE, AUTHENTICATED, OWNER, ROLE
29: from n3tx_core.models.ref import ListRef
30: from n3tx_core.models.relationships import ManyToMany
31: from n3tx_core.utils.decorators import expose_route
32: 
33: 
34: class Tag(ActorModel):
35:     __tablename__ = 'tags'
36:     __storable__ = True
37:     name: str
38: 
39: 
40: class Product(ActorModel):
41:     __tablename__ = 'products'
42:     __storable__ = True
43:     __owner_field__ = 'user_owner'
44:     __access__ = {
45:         'read': ANYONE,
46:         'create': AUTHENTICATED,
47:         'update': OWNER | ROLE('admin'),
48:         'delete': ROLE('admin'),
49:     }
50:     __ui__ = {
51:         'icon': 'box',
52:         'field_order': ['name', 'price', 'description', 'comments', 'tags'],
53:         'groups': {'main': ['name', 'price', 'description'], 'Social': ['comments', 'tags']},
54:         'renderer': {'item': 'ntx-item', 'list': 'ntx-list'},
55:     }
56: 
57:     name: str = Field(min_length=1, max_length=200, json_schema_extra={'ui': {'placeholder': 'Product name'}})
58:     price: float = Field(gt=0, json_schema_extra={'ui': {'widget': 'currency'}})
59:     description: str = Field(default='', json_schema_extra={'ui': {'widget': 'textarea'}})
60:     user_owner: int | None = None
61:     comments: ListRef['Comment'] = Field(default=[])
62:     tags: ManyToMany[Tag] = Field(default=[])
63: 
64:     @expose_route('/discount', methods=['POST'], access=OWNER | ROLE('admin'))
65:     def discount(self, percent: float) -> dict:
66:         return {'new_price': self.price * (1 - percent / 100)}
67: ```
68: 
69: ## BaseUser pattern
70: 
71: ```python
72: from typing import Optional
73: from pydantic import Field
74: from n3tx_core.models.base_user import BaseUser
75: 
76: 
77: class User(BaseUser):
78:     __tablename__ = 'users'
79:     __abstract__ = False
80:     image: Optional[str] = Field(default=None)
81: ```
82: 
83: `BaseUser` provides `name`, `email`, `role`, hidden `password_hash`, `login()`, and `register_user()`.
84: 
85: ## Relationship fields
86: 
87: - Use `ListRef[T]` for parent-scoped child collections such as product comments.
88: - Use `ManyToMany[T]` for shared independent entities such as product tags.
89: - Use `Ref[T]` for a single local or distributed identity pointer.
90: - Use `list[Ref[T]]` for JSON-backed local/distributed pointer arrays.
91: - Do not use `list[T]` or JSON arrays for relationships that need identity,
92:   nested routes, auth, or lifecycle.
93: 
94: ```python
95: from n3tx_core.models.relationships import ManyToMany
96: 
97: class Product(ActorModel):
98:     tags: ManyToMany[Tag] = Field(default=[])
99: ```
100: 
101: `create_app()` / `N3TXApp` discover `ManyToMany` fields and generate link models
102: during bootstrap.
103: 
104: ## Distributed refs
105: 
106: `Ref[T]` means “a pointer to a T actor/model identity Matrix can resolve,” not
107: necessarily an integer FK in this database.
108: 
109: ```python
110: from n3tx_core.models.ref import Ref, ListRef
111: 
112: class Job(ActorModel):
113:     __tablename__ = 'jobs'
114:     __storable__ = True
115: 
116:     owner: Ref[User] | None = None       # local or remote identity pointer
117:     files: list[Ref[File]] = []          # JSON-backed pointer array
118:     comments: ListRef[Comment] = []      # local owned relationship only
119: ```
120: 
121: Accepted ref inputs include local ids, local class-name paths (`/File/12`),
122: current-service API URLs, configured remote HTTP URLs, and canonical distributed
123: refs (`n3tx://storage/File/12`). Configured remote HTTP refs canonicalize to
124: `n3tx://service/Class/id`; arbitrary HTTP(S) URLs remain external links, not
125: Matrix refs.

4: argument-hint: "<networking task>"
5: ---
6: 
7: # N3TX Networking
8: 
9: All external protocol interaction should be translated into TX messages at a network adapter boundary.
10: 
11: ## Network architecture
12: 
13: ```text
14: HTTP / WebSocket / MCP / ActivityPub / external protocol
15:    -> NetworkAdapter
16:    -> TX
17:    -> Matrix
18:    -> ActorModel / Actor
19:    -> TX response/stream
20:    -> protocol response
21: ```
22: 
23: No protocol is special. Adapters translate protocols to the actor system.
24: 
25: ## Built-in adapters
26: 
27: | Adapter | Protocol | Use |
28: |---|---|---|
29: | `NetworkAPI` | HTTP REST | Level 3 app routing |
30: | `NetworkWebSocket` | WebSocket | frontend Matrix bridge |
31: | `NetworkMCP` | MCP JSON-RPC 2.0 | AI/tool clients |
32: | `NetworkAP` | ActivityPub | federation |
33: | `RemoteMatrix` | REST class-name routes + SSE | Distributed `n3tx://service/Class/id` refs and remote streaming |
34: 
35: ## Internal networking rule
36: 
37: Do not make internal backend components call each other through plain HTTP. Use direct model/actor calls at local boundaries or TX/Matrix when crossing actor boundaries.
38: 
39: Distributed backend-to-backend refs are the exception that proves the boundary:
40: code still sends TX to Matrix, and `RemoteMatrix` is the network adapter that
41: translates canonical `n3tx://service/Class/id` targets into remote REST calls.
42: 
43: ```text
44: TX(name='get', target='n3tx://storage/File/12')
45:   -> Matrix adapter fallback
46:   -> RemoteMatrix
47:   -> GET http://storage:7100/File/12
48: 
49: TX(name='generate', target='n3tx://compute/Job/12', meta={'stream': True})
50:   -> Matrix adapter fallback
51:   -> RemoteMatrix.stream()
52:   -> POST remote generated SSE route
53:   -> yields TX stream chunks/errors/end
54: ```
55: 
56: Remote requests carry:
57: 
58: ```text
59: Authorization: Bearer <remote-or-service-token>
60: X-N3TX-Service: <local-service-name>
61: X-N3TX-User: <json-user-context>  # optional
62: ```
63: 
64: Remote response `$id` values pointing at the configured remote URL are
65: canonicalized back to `n3tx://service/Class/id` before returning to callers.
66: 
67: For remote streaming methods, prefer schema-first route resolution. `RemoteMatrix`
68: fetches `GET /{ClassName}` and reads `schema.methods[tx.name].route`, so
69: decorator routes such as `/upload-to-splat` are not guessed from Python method
70: names such as `upload_to_splat`. If schema lookup fails, it falls back to the
71: legacy `/{ClassName}/{id}/{tx.name}` shape for compatibility.
72: 
73: ## External networking rule
74: 
75: If an external API must be called, wrap it:
76: 
77: | Use case | Boundary |
78: |---|---|
79: | App-specific API client | Non-storable `ActorModel` with `@expose_route` methods |
80: | API client with persisted credentials/state | Storable `ActorModel` |
81: | Protocol bridge with custom wire semantics | `NetworkAdapter` |
82: | Agent-usable external capability | Actor/ActorModel method exposed in schema |
83: 
84: ## Example external tool actor
85: 
86: ```python
87: class WebTools(ActorModel):
88:     __tablename__ = 'web_tools'
89:     __storable__ = False
90: 
91:     @expose_route('/scrape', methods=['POST'])
92:     async def scrape(self, url: str) -> dict:
93:         # External HTTP is contained here, behind an actor boundary.
94:         import httpx
95:         async with httpx.AsyncClient() as client:
