526: ### Handler
527: 
528: `ActorModel.handler()` overrides Actor's generic handler with a
529: two-phase dispatch:
530: 
531: 1. **CRUD adapter** (`handler_crud`) -- handles `schema`, `create`,
532:    `get`, `list`, `update`, `delete` by calling StorableMixin methods.
533:    Returns `model_response()` for entities, error TX for failures.
534: 
535: 2. **Generic fallback** -- anything not in the CRUD set falls through
536:    to `getattr(target, tx.name)`, same as plain Actor.
537: 
538: ### Lifecycle Events
539: 
540: After successful create/update/delete, `_publish_lifecycle()` sends a
541: `LIFECYCLE` TX to registered subscribers (fire-and-forget via
542: `asyncio.create_task`). Subscribers are future consumers: federation
543: outbox, agent monitor, audit logger, websocket bridge.
544: 
545: ```python
546: # Internal — published automatically after CRUD ops
547: TX(name='LIFECYCLE', source='products', target=subscriber_addr,
548:    data={'event': 'after_create', 'entity': {...}})
549: ```

553: ## NetworkAdapter -- Protocol Bridge
554: 
555: ALL external protocol interaction flows through a `NetworkAdapter`.
556: Each adapter is an Actor registered as a Matrix child that translates
557: between an external protocol and TX messages.
558: 
559: ```
560: External Protocol  →  NetworkAdapter  →  TX  →  Matrix  →  ActorModel
561:                   ←                  ←  TX  ←          ←
562: ```
563: 
564: ### Base Class
565: 
566: `NetworkAdapter(Actor, auto_register=False)` lives in `api/network_adapter.py`:
567: 
568: ```python
569: from n3tx.core.api.network_adapter import NetworkAdapter
570: 
571: class MyAdapter(NetworkAdapter, auto_register=False):
572:     def __init__(self, **kwargs):
573:         kwargs.setdefault('addr', 'myadapter')
574:         super().__init__(**kwargs)
575: 
576:     def SOME_MESSAGE(self, data, tx):
577:         return {'handled': True}
578: ```
579: 
580: Key methods:
581: 
582: | Method | Purpose |
583: |--------|---------|
584: | `request(tx, timeout)` | Send TX, await single correlated response via asyncio.Future |
585: | `stream(tx, timeout)` | Send TX, yield multiple correlated chunks via asyncio.Queue |
586: | `inbox(tx)` | Intercepts correlated replies (Future for request, Queue for stream) |
587: 
588: `request()` bridges synchronous protocols (HTTP, JSON-RPC) to the
589: fire-and-forget actor model. It creates a Future keyed by `tx.uuid`,
590: sends the TX, and awaits the reply. When the reply arrives at
591: `inbox()`, its `meta['req']` matches the original uuid, resolving
592: the Future.
593: 
594: `stream()` works like `request()` but for multi-reply interactions.
595: It creates an `asyncio.Queue` keyed by `tx.uuid`, sends the TX, and
596: yields chunks as they arrive. The stream terminates when a
597: `stream_end` or error TX is received. `inbox()` detects whether the
598: pending entry is a Future or Queue and dispatches accordingly.

610: ### RemoteMatrix Adapter
611: 
612: `RemoteMatrix` handles absolute HTTP(S) targets by reusing existing class-name
613: REST routes. Configured remotes provide tokens and API-prefix disambiguation,
614: not identity translation:
615: 
616: ```python
617: from n3tx_actors.api.remote_matrix import RemoteMatrix, MatrixReferenceResolver
618: 
619: remote = RemoteMatrix(remotes={'storage': {'url': 'http://storage:7100'}})
620: matrix.register(remote)
621: matrix.register_adapter(remote)
622: storage.set_reference_resolver(MatrixReferenceResolver(matrix))
623: ```
624: 
625: | TX | REST call |
626: |---|---|
627: | `TX(name='get', target='http://storage:7100/File/12')` | `GET http://storage:7100/File/12` |
628: | `TX(name='process', target='http://storage:7100/File/12')` | `POST http://storage:7100/File/12/process` |
629: | `TX(name='generate', target='http://compute:7200/Job/12', meta={'stream': True})` | `POST http://compute:7200/Job/12/<schema route>` as SSE |
630: 
631: `RemoteMatrix.stream(tx)` provides distributed streaming for canonical remote
632: refs. It calls the remote generated SSE route, parses `event: chunk|done|error`
633: frames into full TX envelopes, and yields chunks until an error TX or
634: `meta.stream_end` is received. Streaming route resolution is schema-first:
635: `GET /{ClassName}` supplies `schema.methods[tx.name].route`, so decorator routes
636: such as `/upload-to-splat` do not need to be guessed from Python method names.
637: If the schema route cannot be resolved, the adapter falls back to the legacy
638: `/{ClassName}/{id}/{tx.name}` shape.
639: 
640: Remote requests carry backend trust and user continuity through headers:
641: 
642: ```text
643: Authorization: Bearer <remote-or-service-token>
644: X-N3TX-Service: <local-service-name>
645: X-N3TX-User: <json-user-context>  # optional
646: ```
647: 
648: The receiving service accepts the request when the bearer token matches its
649: configured `SERVICE_TOKEN`, then installs forwarded user JSON into
650: `request.state.user` so generated routes and ActorModel ABAC remain the single

1: # N3TX Agents
2: 
3: LLM-powered reasoning via the actor system.
4: 
5: **A Model is an Agent, an Agent is an Actor, and an Actor is a Tool collection.**
6: 
7: Every Actor with `@expose_route` methods is a set of callable tools.
8: An Agent is an Actor that reasons — it has a prompt, an LLM, and a list
9: of other actors it can talk to. The union of all `@expose_route` methods
10: on those actors forms the agent's available tool set.
11: 
12: Agents are **data, not code**. The primary pattern is dynamic
13: instantiation — create agents via API, store them in DB, load them at
14: runtime. Subclasses are supported but not the primary path.
15: 
16: ---
17: 
18: ## Quick Start
19: 
20: ### Path A: Dynamic Agents (primary)
21: 
22: Agents are instances of `AgentActor`. Configuration lives in fields.
23:

36:     __storable__ = False
37:

50:     constraints={"max_iterations": 30},
51: )

53: # Trigger the agent
54: result = await scanner.run(task="Find grants about renewable energy")

75: ### Path B: Agentic Model Methods (secondary)
76: 
77: Any `ActorModel` with `__agent__ = True` gets `AgentMixin` injected.
78: Its methods can call `self.agent_run()` internally — the caller doesn't
79: know or care that an LLM is involved.
80: 
81: ```python
82: class Product(ActorModel):
83:     __tablename__ = 'products'
84:     __storable__ = True
85:     __agent__ = True          # injects AgentMixin
86: 
87:     name: str
88:     price: float
89: 
90:     @expose_route('/create_from_text', methods=['POST'])
91:     async def create_from_text(self, text: str, tools: list = []) -> str:
92:         """LLM parses freeform text into a Product."""
93:         result = await self.agent_run(
94:             prompt="Parse the text into a Product with name and price. "
95:                    "Use products_create to save it.",
96:             tools=["products"] + tools,
97:             task=text,
98:         )
99:         return result['answer']
100: ```

108: ### @expose_route = Tool
109: 
110: No new `@tool` decorator. The existing `@expose_route` already provides
111: everything a tool needs:

134: ### Pydantic AI Is the Engine
135: 
136: N3TX does not build an LLM client, agent loop, or context manager.
137: [Pydantic AI](https://ai.pydantic.dev/) provides all of that:
138: 
139: | Concern | Pydantic AI provides |
140: |---------|---------------------|
141: | LLM calls | Multi-provider (Ollama, Anthropic, OpenAI, Google, etc.) |
142: | Agent loop | ReAct-style tool calling with automatic retries |
143: | Tool calling | Argument validation + result serialization |
144: | Structured output | `output_type=` with Pydantic model validation |
145: | Conversation history | `result.all_messages()` for continuation |
146: | Usage tracking | `result.usage()` (tokens, requests) |
147: | Error handling | `ModelRetry`, `UsageLimitExceeded`, retries |
148: | Safety limits | `UsageLimits(request_limit=, token_limit=)` |
149: 
150: N3TX's job is purely the **binding layer**: discover tools from actors,
151: route tool calls through Matrix as TX, persist agent state, publish
152: lifecycle events.
153:

200: ### AgentMixin (`mixin.py`)
201: 
202: Injected into any model with `__agent__ = True` via `ProtoModel`'s mixin registry.
203: Same injection pattern as `StorableMixin`:
204: 
205: ```python
206: __storable__ = True  -->  injects StorableMixin  (special-cased in core)
207: __agent__    = True  -->  injects AgentMixin     (registered by n3tx_agents.__init__)
208: __ui__       = {...} -->  injects ViewableMixin  (registered by n3tx_ui.__init__)
209: ```
210: 
211: **Import ordering requirement**: `n3tx_agents` (or just `import n3tx_agents`) must
212: be imported **before** any model with `__agent__ = True` is defined. The mixin
213: registry is populated at `n3tx_agents` import time. Applications must put
214: `import n3tx_agents` before their model imports in `main.py`.
215: 
216: ```python
217: # main.py — correct order
218: import n3tx_agents   # registers AgentMixin in proto_model._mixin_registry
219: from models import Product  # __agent__ = True fires → AgentMixin injected
220: 
221: # main.py — wrong order (AgentMixin silently not injected)
222: from models import Product  # __agent__ = True fires with empty registry
223: import n3tx_agents          # too late
224: ```

261: 1. Resolves LLM from 3-tier cascade (kwargs > model config > AGENT_DEFAULTS)

346: ### Tool Discovery (`tools.py`)
347: 
348: Discovers tools from actor addresses by reading their schemas.
349: 
350: #### `discover_tools(actor_addrs, root) -> list[ToolSpec]`
351: 
352: For each address in `actor_addrs`:
353: 
354: 1. Looks up the actor in Matrix children
355: 2. Gets the model class and calls `cls.schema()`
356: 3. If the model is **storable**: generates CRUD tool specs (`list`, `get`, `create`, `update`, `delete`)
357: 4. For all `@expose_route` methods in `schema.methods`: generates method tool specs
358: 
359: **Tool naming convention:** `{tablename}_{method}` (e.g., `grants_create`, `web_tools_scrape`).
360: 
361: **CRUD tools** for storable models:
362: 
363: | Tool | Description | Required params |
364: |------|-------------|-----------------|
365: | `{t}_list` | List records | (none, optional `limit`/`offset`) |
366: | `{t}_get` | Get by ID | `id` |
367: | `{t}_create` | Create record | writable fields |
368: | `{t}_update` | Update record | `id` + writable fields |
369: | `{t}_delete` | Delete by ID | `id` |
370: 
371: **Method tools** from `@expose_route`:
372: 
373: - Parameters come from `schema.methods[name].parameters`
374: - The `user` parameter is filtered out (injected server-side)
375: - Instance methods automatically get an `id` parameter prepended
376: 
377: #### `ToolSpec`
378: 
379: ```python
380: @dataclass
381: class ToolSpec:
382:     actor_addr: str     # Target actor address (e.g., 'grants')
383:     method_name: str    # Method/action name (e.g., 'create')
384:     tool_name: str      # LLM-facing name (e.g., 'grants_create')
385:     description: str    # Human-readable description
386:     parameters: dict    # JSON Schema for parameters
387: ```
