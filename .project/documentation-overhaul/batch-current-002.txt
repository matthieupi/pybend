275: ### Backend (Python/FastAPI)
276: 
277: Models extend `ProtoModel` (or `ActorModel` for actor capabilities). `ProtoModel.schema()` orchestrates the schema pipeline, `model_response()` runs the dump pipeline. Models are registered via `register_model()` and routes auto-generated via `register_routes()`. See `BACKEND.md` for the full backend pipeline diagram and key files.
278: 
279: ### Frontend (Vanilla JS Web Components)
280: 
281: The frontend bootstraps by fetching schema from the backend. `N3TX.SCHEMA()` creates DynamicClasses via `prototype()`, which are then rendered by Web Components (`ntx-list`, `ntx-item`, `ntx-method`, `ntx-stream`) with forms generated by `Formidable`. See `FRONTEND.md` for the frontend architecture diagram and key files, and `packages/n3tx-ui/docs/styling.md` for the theme/token contract and frontend verification workflow.
282: 
283: ### Data Flow: Request Lifecycle
284: 
285: 1. Frontend `<ntx-list model="Product">` triggers schema fetch → `GET /Product`
286: 2. Backend returns JSON Schema with `$schema`, `$id`, `properties`, `$defs`, `methods`
287: 3. Frontend creates DynamicClass from schema, registers nested `$defs` models
288: 4. DynamicClass triggers `READ` → `GET /products?limit=20&offset=0` (paginated)
289: 5. Backend returns `{data: [...], meta: {total, limit, offset, has_more}}` with `$schema`/`$id` on each item
290: 6. Frontend creates instances, renders via `ntx-item` components with "Load More" button if `has_more`

292: ## Schema-Driven Development
293: 
294: Write a Python model, get a working full-stack application. The model definition is the only thing a developer writes. Everything else — API, validation, storage, UI, permissions, navigation — is derived from the schema that model produces. Any project can be transformed into a full stack application by turning a few classes into models.

475: ## Cross-Cutting Patterns
476: 
477: ### Custom Methods
478: ```python
479: @expose_route('/like', methods=['POST'], access=AUTHENTICATED)
480: def like(self) -> str:
481:     ...
482: ```
483: Appears in schema under `methods`, frontend renders via `<ntx-method>` (or `<ntx-stream>` for streaming methods). The `access=` parameter controls authorization. The `stream=True` parameter marks the method as streaming.
484: 
485: ### Streaming Methods
486: Custom methods can stream progressive results via SSE or WebSocket:
487: 
488: ```python
489: @expose_route('/generate', methods=['POST'], stream=True, access=AUTHENTICATED)
490: async def generate(self):
491:     for i in range(5):
492:         await asyncio.sleep(0.1)
493:         yield {'chunk': f'Part {i}'}
494: ```
495: 
496: SSE wire format: `event: chunk|done|error`, `data: {json}`. Stream protocol uses `meta: {req, stream: true, seq: N}` for chunk correlation and `meta: {stream_end: true}` for termination.
497: 
498: #### Schema-Declared Stream Events
499: 
500: Streaming methods can declare their event vocabulary with `events=` on `@expose_route`. Event types are non-storable `ProtoModel` subclasses:
501: 
502: ```python
503: class TextChunk(ProtoModel):
504:     text: str = Field(default='')
505: 
506: @expose_route('/stream', methods=['POST'], stream=True,
507:               events={'text': TextChunk, 'done': DoneChunk})
508: async def stream_method(self, task: str):
509:     yield {'name': 'text', 'data': {'text': 'hello'}}
510: ```
511: 
512: Events appear in schema as `methods[m].events` with full JSON Schema per event type. See `docs/AGENTS.md` → Streaming for the complete pattern.
513: 
514: #### Frontend NTTStreamAgent
515: 
516: `NTTStreamAgent` (`n3tx-agents/static/components/ntx-stream-agent.js`) extends `NTTStream` with rich agent output rendering — typed entries (thinking, tool calls, text), markdown rendering, and tool result cards. Components that need agent-style streaming extend `NTTStreamAgent` and override UPPERCASE handlers:
517: 
518: ```javascript
519: class MyComponent extends NTTStreamAgent {
520:     TEXT(data, meta)  { /* data.text */ }

521:     DONE(data, meta)  { /* data.answer */ }
522:     STREAM_END(data)  { /* cleanup */ }
523: }
524: ```
525: 
526: For simpler progressive output (plain chunks), extend `NTTStream` directly.
527: 
528: **Component hierarchy**: `Component → NTTMethod → NTTStream → NTTStreamAgent → (app subclasses)`
529: 
530: **prerender()/render() lifecycle**: `prerender()` is called from `connectedCallback()` before schema loads — use it for structural DOM. `render()` is the schema-aware pass — it is additive and should never wipe `prerender()` output.
531: 
532: **UPPERCASE convention**: TX inbox handlers are always UPPERCASE. This mirrors the backend actor handler pattern.

534: ### Authenticated User Injection
535: Custom methods receive the authenticated user by declaring a `user` parameter:
536: ```python
537: @expose_route('/comment', methods=['POST'])
538: def comment(self, comment: Comment, user: User = None) -> str:
539:     comment.user_owner = user.id if user else 1
540:     ...
541: ```
542: The route layer's `_resolve_user()` resolves the type hint from the JWT token. The `user` param is never read from the request body.

544: ### Actor System
545: For full details, read `docs/ACTORS.md` and `packages/n3tx-actors/docs/`.
546: 
547: **`fullmethod`/`fullproperty` descriptors** (in `n3tx_core/utils/descriptors.py`): Generic descriptors for unified class/instance dispatch. Used by both actors and agents.
548: 
549: **Actor base class** extends PydanticBaseModel via `ActorMeta` metaclass. `send()` three-case routing, `use()` interceptors, class + instance state.
550: 
551: **TX** is a dataclass message envelope: `reply()`, `error()`, `is_error`, `stream_chunk()`, `stream_end()`.
552: 
553: **Matrix** extends Actor: root actor, `has()`, adapter delegation, module-level `matrix` singleton.
554: 
555: **ActorProxy** wraps any class as a routable actor without MI.

557: ### ActorModel Pattern
558: ```python
559: from n3tx_actors.models.actor_model import ActorModel
560: 
561: class Product(ActorModel):
562:     __tablename__ = 'products'
563:     __storable__ = True
564:     ...
565: ```
566: One import change from ProtoModel. `ActorModel(Actor, ProtoModel)` is the bridge class. CRUD via `handler_crud()`, lifecycle events, generic handler fallback.
567: 
568: ### AgentMixin — Self-Aware Models
569: For full details, read `docs/AGENTS.md` and `packages/n3tx-agents/docs/`.
570: 
571: `__agent__ = True` gives a model LLM-powered reasoning. Six `@fullmethod` methods: `ctx()`, `tools()`, `agentic()`, `run()`, `agentic_stream()`, `run_stream()`.
572: 
573: **Config cascade** (3-tier): `config.AGENT_DEFAULTS` < `__agent__` dict < `agentic()` kwargs.
574: 
575: **AgentMixin vs AgentActor**: AgentMixin derives config from model definition; AgentActor stores config in DB fields.
576: 
577: **Import ordering**: `n3tx_agents` (or `import n3tx_agents`) must be imported **before** any model with `__agent__ = True` is defined. `n3tx_agents.__init__` calls `register_mixin('__agent__', AgentMixin)` which populates `proto_model._mixin_registry`. If a model is defined before this call, the mixin is silently not injected.

579: ### Three Levels of N3TX
580: ```python
581: # Level 1 — ProtoModel + direct routes (no actors)
582: app = create_app(models=[Product], storage="sqlite:///app.db")
583: 
584: # Level 2 — ActorModel + direct routes (actor capabilities, same HTTP layer)
585: app = create_app(models=[Product], storage="sqlite:///app.db")
586: 
587: # Level 3 — ActorModel + NetworkAPI (full actor routing)
588: app = create_app(models=[Product], storage="sqlite:///app.db", routing='actor')
589: ```

591: ### Two-Tier Auth (Level 3)
592: - **Tier 1**: `auth_interceptor` on `NetworkAPI.request()` — fast gate at protocol boundary
593: - **Tier 2**: `ActorModel._authorize()` in `handler_crud()` — full ABAC with resource instance
594: 
595: Level 1/2 use `routes_fastapi.py`'s single-pass authorization.
596: 
597: ### JSON Fields (dict/list Storage)
598: `dict` and `list` fields are transparently serialized to JSON TEXT in SQLite. See `packages/n3tx-core/docs/storage.md` for details.
599: 
600: ### Generated HTTP Partial Updates
601: 
602: Generated direct and actor HTTP `PUT` routes, direct `Model.update(id, patch)`,
603: raw actor TX updates, and agent update tools share one partial-update contract.
604: Omitted fields remain unchanged. The supplied patch is merged with the current
605: entity, validated through the original model, and only supplied fields reach
606: storage. Explicit collection values are complete replacements and writes remain
607: last-write-wins; prefer domain-specific `@expose_route` methods for atomic
608: append/remove/toggle mutations. Canonical guidance:
609: `docs/API_CRUD_ENDPOINTS.md#update-resource`.

627: Use the repository-managed Python virtual environment at `/workspace/.venv-agents` for backend and example test execution. Invoke Python tools through that environment explicitly so agents share one predictable dependency surface:
628: 
629: ```bash
630: cd /workspace && .venv-agents/bin/python scripts/test-backend.py --list
631: cd /workspace && .venv-agents/bin/python -m pytest packages/n3tx-core/src/n3tx_core/tests/unit/
632: ```
633: 
634: If a test suite fails because a Python package is missing, agents may install the missing dependency into `.venv-agents` and retry the same verification command:
635: 
636: ```bash
637: cd /workspace && .venv-agents/bin/python -m pip install <package>
638: ```
639: 
640: Do not install missing test dependencies globally or into unrelated virtual environments. Prefer the narrowest dependency needed by the failing suite, and report any dependency installation in the final verification summary.
641: 
642: Use the backend runner when checking multiple backend suites from one command. It executes each suite in a separate process with the correct working directory and `PYTHONPATH`, avoiding root-level pytest import collisions between example apps:
643: 
644: ```bash
645: cd /workspace && .venv-agents/bin/python scripts/test-backend.py --list
646: cd /workspace && .venv-agents/bin/python scripts/test-backend.py --suite core -- -q
647: cd /workspace && .venv-agents/bin/python scripts/test-backend.py --short
648: cd /workspace && .venv-agents/bin/python scripts/test-backend.py -- -q
649: cd /workspace && .venv-agents/bin/python scripts/test-backend.py --fail-fast -- -q  # optional: stop after first failing suite
650: ```
