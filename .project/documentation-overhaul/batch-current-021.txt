288: ### 6. Network Adapters
289: 
290: **Location**: `api/network_adapter.py`, `api/network_mcp.py`, `api/network_ap.py`
291: 
292: ALL external protocol interaction flows through a `NetworkAdapter(Actor)`. Each adapter translates between an external protocol and TX messages routed through the Matrix.
293: 
294: ```python
295: class NetworkAdapter(Actor, auto_register=False):
296:     """Base class — request/response correlation via asyncio.Future."""
297: 
298:     async def request(self, tx: TX, timeout: float = 30.0) -> TX:
299:         # Sends TX, awaits correlated reply via Future matching
300: 
301:     async def inbox(self, tx: TX) -> None:
302:         # Intercepts correlated replies before normal handler dispatch
303: 
304: class NetworkMCP(NetworkAdapter):    # MCP JSON-RPC 2.0
305: class NetworkAP(NetworkAdapter):     # ActivityPub federation
306: class NetworkAPI(NetworkAdapter):    # HTTP REST (Level 3 actor routing)
307: class NetworkWebSocket(NetworkAdapter): # Frontend Matrix bridge
308: class RemoteMatrix(NetworkAdapter):  # HTTP(S) refs -> remote class-name REST
309: # Transient adapters created per agent_run() for tool call correlation
310: ```
311: 
312: **Pattern**: Adapter Pattern (protocol translation) + Correlation Pattern (request/response over async messaging)
313: 
314: **Key Design Decision**: The HTTP API itself is a NetworkAdapter (`NetworkAPI`), meaning ALL external interaction — REST, MCP, ActivityPub, WebSocket — flows through the same architecture. No protocol is special.
315: 
316: #### HTTP(S) refs through RemoteMatrix
317: 
318: ```text
319: Model field value: Ref[T] / list[Ref[T]]
320:         |
321:         v
322: models/ref.py validates the absolute entity URL
323:         |
324:         v
325: SQLiteStorage stores/returns the URL unchanged
326:         |
327:         v

329:         |
330:         v
331: Matrix request -> RemoteMatrix adapter fallback
332:         |
333:         +-- GET  http://remote/ClassName/id
334:         +-- POST http://remote/ClassName/id/method

336: 
337: Default storage behavior remains local-only. Without a resolver, remote refs are
338: preserved as strings; populated `list[Ref[T]]` fields include per-ref errors
339: instead of failing the parent read. In actor routing, `create_app(...,
340: routing='actor', remotes={...})` registers `RemoteMatrix` and injects a
341: `MatrixReferenceResolver` into compatible storage backends.

343: ### 6b. Interceptors (`use()`)
344: 
345: **Location**: `actors/actor.py` (base mechanism), `api/auth_interceptor.py` (auth implementation)
346: 
347: Every Actor can register TX interceptors on any of its TX-handling methods via `use()`:
348: 
349: ```python
350: # Register on specific method targets
351: actor.use(auth_check, on='inbox')      # before inbox processes
352: actor.use(rate_limit, on='send')       # before send routes
353: adapter.use(jwt_auth, on='request')    # before request sends+awaits
354: 
355: # Decorator forms
356: @actor.use                             # defaults to on='inbox'
357: async def log_all(tx: TX) -> TX: ...
358: 
359: @adapter.use(on='request')
360: async def authenticate(tx: TX) -> TX: ...
361: ```
362: 
363: **Interceptor signature**: `async (TX) -> TX`. Return error TX to short-circuit the chain.
364: 
365: **Chain behavior**:
366: - Class-level interceptors run first, then instance-level (combined via `_get_interceptors`)
367: - Chain stops on first error TX (`tx.is_error`)
368: - `inbox()` error: sends error TX back via `send()` (caller gets rejection)
369: - `send()` error: drops silently (outbound message never routed)
370: - `request()` error: returns error TX immediately (never enters actor system)
371: 
372: **Per-adapter, not global**: Each adapter registers its own interceptors. Authentication is protocol-specific (JWT for HTTP, API key for MCP, HTTP signatures for AP). Universal authorization is handled by Tier 2 handler guard in ActorModel.

375:

402: ### 7. Three Levels of N3TX
403: 
404: N3TX supports three routing levels — developers choose based on their needs:
405: 
406: ```
407: Level 1: ProtoModel  + routes_fastapi.py   → plain HTTP, no actors
408: Level 2: ActorModel  + routes_fastapi.py   → actor capabilities, same HTTP layer
409: Level 3: ActorModel  + NetworkAPI adapter   → actors all the way down
410: ```
411: 
412: Each level is one change from the previous. Model base class swap for Level 2, `routing='actor'` flag for Level 3.
413: 
414: ```python
415: # Level 1 — Plain HTTP (default)
416: app = create_app(models=[Product, User], storage="sqlite:///app.db")
417: 
418: # Level 2 — Actor capabilities, same HTTP routes
419: # Just change ProtoModel → ActorModel in your models
420: app = create_app(models=[Product, User], storage="sqlite:///app.db")
421: 
422: # Level 3 — Full actor routing through Matrix
423: app = create_app(models=[Product, User], storage="sqlite:///app.db", routing='actor')
424: ```
425: 
426: **Level 1/2** use `routes_fastapi.py` route factories (direct StorableMixin calls).
427: **Level 3** uses `NetworkAPI` adapter (HTTP → TX → Matrix → ActorModel → StorableMixin).
428: 
429: `routes_fastapi.py` is never modified — Level 3 is purely additive.

431: ### 8. Agent System
432: 
433: **Location**: `agents/mixin.py`, `agents/actor.py`, `agents/tools.py`, `agents/deps.py`, `agents/schema_ext.py`
434: 
435: LLM-powered agents built on [Pydantic AI](https://ai.pydantic.dev/). N3TX provides only the binding layer — tool discovery from actor schemas, TX routing for tool calls, and agent state persistence.
436: 
437: **Core insight**: Every Actor with `@expose_route` methods is a tool collection. An Agent is an Actor that reasons.
438: 
439: ```python
440: # AgentMixin — injected when __agent__ = True (same pattern as StorableMixin)
441: class AgentMixin:
442:     # agentic() = policy layer (config cascade)
443:     async def agentic(target, task: str, **kwargs) -> dict: ...
444:     # run() = engine (explicit params, no config magic)
445:     async def run(target, task: str, prompt: str, tools: list, ...) -> dict:
446:         # 1. Resolve LLM from config cascade
447:         # 2. discover_tools(tools, root) — read schemas, build ToolSpecs
448:         # 3. Create Pydantic AI Agent with generated tool functions
449:         # 4. Run agent loop — tool calls route through Matrix.request()
450:         # Returns: {answer, usage: {input_tokens, output_tokens, requests}, messages}
451: 
452: # AgentActor — concrete model whose instances ARE agents (data, not code)
453: class AgentActor(ActorModel):
454:     __agent__ = True        # gets AgentMixin
455:     __storable__ = True     # stored in DB
456: 
457:     name: str               # Human-readable name
458:     prompt: str             # System prompt
459:     tools: list[AgentTool]     # Ordered hydrated tool records
460:     llm: str                # Pydantic AI provider:model string
461:     constraints: dict       # {max_iterations, ...}
462: 
463:     @expose_route('/agentic', methods=['POST'])
464:     async def agentic(self, task: str, **kwargs) -> str: ...
465: ```
466: 
467: **Two paths, one mechanism**:
468: - **Path A**: `AgentActor` instances (dynamic agents — created via API/DB/code)
469: - **Path B**: Any model with `__agent__ = True` (agentic methods — `self.agentic()`)
470: 
471: **Tool discovery**: `discover_tools(actor_addrs, root)` reads `schema.methods` from Matrix children. Storable models get CRUD tools (list, get, create, update, delete). All `@expose_route` methods become tools. Tool functions use `exec()` for dynamic typed signatures (same as dataclasses).
472: 
473: **Tool call routing**: Generated tool functions create TX messages and send them through `NetworkAdapter.request()` for Future-based correlation. Error TXs raise `ModelRetry` (Pydantic AI retries the LLM).
474: 
475: **Schema extension**: `@schema_extension(after='methods')` adds `agent: {enabled, agentic_endpoint}` to JSON Schema output for agent-capable models.
476: 
477: See [`src/n3tx/core/agents/README.md`](../agents/README.md) for full documentation.

676: ## Design Patterns
677: 
678: ### 1. Mixin Pattern
679: 
680: **StorableMixin**, **ViewableMixin**, and **AgentMixin** are dynamically injected into models via `__init_subclass__`. `StorableMixin` is special-cased in core (it rewrites FK annotations). External mixins use the `register_mixin()` registry:
681: 
682: ```python
683: # Before
684: class User(ProtoModel):
685:     __storable__: ClassVar[bool] = True
686: 
687: # After __init_subclass__
688: class User(StorableMixin, ProtoModel):
689:     # Now has .save(), .create(), .list(), etc.
690: 
691: # Agent injection — n3tx_agents must be imported first
692: import n3tx_agents  # registers AgentMixin via register_mixin()
693: 
694: class Scanner(ActorModel):
695:     __agent__ = True
696: 
697: # After __init_subclass__
698: class Scanner(AgentMixin, ActorModel):
699:     # Now has .agentic(), .run(), .ctx(), .tools(), etc.
700: 
701: # ViewableMixin injection — n3tx_ui must be imported first
702: import n3tx_ui  # registers ViewableMixin via register_mixin()
703: 
704: class Product(ProtoModel):
705:     __ui__ = {'field_order': ['name', 'price']}  # also triggers injection
706: 
707: # After __init_subclass__
708: class Product(ViewableMixin, ProtoModel):
709:     # schema() now emits schema['ui'] from __ui__
710: ```
711: 
712: **Extension API** — external packages register their own mixins:
713: 
714: ```python
715: from n3tx_core.models.proto_model import register_mixin
716: register_mixin('__my_flag__', MyMixin)                         # explicit flag
717: register_mixin('__viewable__', ViewableMixin, also_if=['__ui__'])  # guardrail
718: ```
719: 
720: **Benefits**:
721: - Opt-in functionality
722: - Keeps concerns separated (core has zero knowledge of ViewableMixin/AgentMixin)
723: - No inheritance pollution
724: - Extensible: third-party packages can register their own mixins
725:

791: ### 6. Two-Pass Route Registration
792: 
793: Routes are registered in two passes to avoid path conflicts:
794: 
795: ```
796: Pass 1: Collection routes (static segments)
797:   /products/comments     (GET — all comments across products)
798:   /products/likes        (GET — all favorites across products)
799: 
800: Pass 2: CRUD routes (parameterized segments)
801:   /products/{id}         (GET/PUT/DELETE)
802:   /products/{parent_id}/comments/{id}  (nested CRUD)
803: ```
804: 
805: This ensures `/products/comments` is matched as a collection route, not as `/products/{id}` with `id="comments"`.
806: 
807: #### Generated update boundary
808: 
809: Generated FastAPI update handlers preserve the raw patch and delegate complete
810: state validation to the existing model update path:
811: 
812: ```text
813: HTTP PUT body
814:   -> preserve supplied fields
815:   -> merge with current entity
816:   -> validate through the original ProtoModel
817:   -> storage writes only supplied fields
818: ```
819: 
820: HTTP clients, direct `Model.update(id, patch)`, raw actor TX updates, and agent
821: update tools therefore share one partial-update contract. Omitted fields remain
822: unchanged; explicit `[]` or `{}` values clear their complete stored fields. See
823: [API CRUD Endpoints](API_CRUD_ENDPOINTS.md#update-resource).
