1: # Tool Discovery
2: 
3: > Part of [n3tx-agents](../README.md)
4: 
5: ## What This Covers
6: 
7: The pipeline from actor addresses to callable Pydantic AI tools:
8: `discover_tools()` -> `ToolSpec` -> `create_tool_function()` -> `make_tool()`.
9: Also covers the schema extension that provides the LLM-clean schema pipeline.
10: 
11: ## Architecture
12: 
13: ```
14: actor addresses        e.g. ['grants', 'web_tools']
15:     |
16:     v
17: discover_tools()       reads schema() from Matrix children
18:     |
19:     +-- _crud_tool_specs()     CRUD for storable models (list/get/create/update/delete)
20:     +-- _method_tool_specs()   @expose_route methods (scrape, extract, ...)
21:     |
22:     v
23: list[ToolSpec]         {actor_addr, method_name, tool_name, description, parameters}
24:     |
25:     v
26: make_tool(spec)        per spec:
27:     |
28:     +-- create_tool_function(spec)   exec()-generated async fn with typed params
29:     +-- pydantic_ai.Tool(fn, ...)    wraps in Pydantic AI Tool
30:     |
31:     v
32: list[Tool]             registered on pydantic_ai.Agent
33: ```
34: 
35: Tool calls at runtime route through `_route_tool_call()`:
36: 
37: ```
38: LLM calls tool  ->  generated fn(ctx, params)  ->  _route_tool_call()
39:     |
40:     +-- creates TX(name=method, target=actor_addr, data=params)
41:     +-- non-stream: Matrix.request(tx)  -- Future-based correlation
42:     +-- stream=True: Matrix.stream(tx)  -- Queue-based correlation
43:     +-- streamed routes are consumed server-side to completion
44:     +-- returns one final JSON string to the LLM
45:     +-- on error TX: raises ModelRetry (LLM retries)
46: ```
47: 
48: ## Interface
49: 
50: ### `discover_tools(actor_addrs, root, caller_addr=None) -> list[ToolSpec]`
51: 
52: | Param | Type | Purpose |
53: |-------|------|---------|
54: | `actor_addrs` | list[str] | Actor addresses to discover tools from |
55: | `root` | Matrix | Matrix root for child lookup |
56: | `caller_addr` | str | Calling agent address (excluded to prevent self-loops) |
57: 
58: **Behavior**:
59: - Looks up each address in `root._children`
60: - Calls `cls.schema()` on found actors
61: - Storable models get 5 CRUD ToolSpecs (list, get, create, update, delete)
62: - All `@expose_route` methods get a ToolSpec each
63: - Streaming `@expose_route(..., stream=True)` methods stay in the tool set and
64:   are marked as streaming instead of being filtered out
65: - AgentActor subclasses auto-exclude `run` and `stream_run` methods
66: - Missing actors log a warning and are skipped
67: 
68: ### `ToolSpec` (dataclass)
69: 
70: ```python
71: @dataclass
72: class ToolSpec:
73:     actor_addr: str     # Target actor (e.g. 'products')
74:     method_name: str    # Action name (e.g. 'create', 'scrape')
75:     tool_name: str      # LLM-facing name (e.g. 'products_create')
76:     description: str    # Human-readable description
77:     parameters: dict    # JSON Schema for input parameters
78:     stream: bool = False
79: ```
80: 
81: Tool names follow `{tablename}_{method}` convention.
82: 
83: ### `create_tool_function(spec) -> async function`
84: 
85: Generates an async function via `exec()` with properly typed parameters
86: from the ToolSpec's JSON Schema. The function's signature is introspected
87: by Pydantic AI for JSON Schema generation.
88: 
89: Type mapping: `string->str`, `integer->int`, `number->float`,
90: `boolean->bool`, `array->list`, `object->dict`.
91: 
92: Required params have no default. Optional params default to `None`.
93: The `ctx` parameter (RunContext[AgentDeps]) is always first.
94: 
95: ### `make_tool(spec) -> pydantic_ai.Tool`
96: 
97: Wraps `create_tool_function()` output in a `pydantic_ai.tools.Tool` with
98: `takes_ctx=True`.
99: 
100: ### `_route_tool_call(ctx, target_addr, method_name, data, stream=False) -> str`
101: 
102: Internal. Creates a TX, sends via `Actor.root().request()` or
103: `Actor.root().stream()`, and returns response data as JSON string. On error
104: TX, raises `pydantic_ai.ModelRetry`.
105: 
106: For streaming tool methods, `_route_tool_call()` consumes the stream and
107: collapses it into a single result for the LLM:
108: 
109: - prefer a yielded `{'name': 'done', 'data': ...}` payload
110: - otherwise fall back to concatenated text chunks
111: - otherwise return collected event payloads
112:

137: ## LLM Schema Pipeline
138: 
139: The `schema_ext` module registers two pipelines:
140: 
141: **Default pipeline** -- `agent` stage (after `methods`): Adds `agent`
142: section to JSON Schema for `__agent__ = True` models. Contains `enabled`,
143: `config` (safe keys only -- no LLM credentials), `methods` list, and
144: `agentic_endpoint` (for AgentActor subclasses).
145: 
146: **LLM pipeline** -- `base` + `clean` stages: Produces a clean schema
147: for LLM context consumption. Strips frontend-only keys (`ui`, `$id`,
148: `$schema`, `additionalProperties`), removes `$defs`, filters hidden/
149: protected properties, strips routing metadata from methods, removes
150: `user` parameter from method signatures.
151: 
152: ```python
153: from n3tx_core.models.proto_schema import run_pipeline
154: cleaned = run_pipeline(Product, pipeline='llm')
155: ```
156: 
157: ## Gotchas
158: 
159: - CRUD tool specs filter out `id`, protected, and hidden fields from
160:   writable properties. The `id` field is only included in get/update/delete
161:   where it is required.
162: - Instance methods (scope == `'instancemethod'`) auto-prepend an `id`
163:   parameter and add it to `required`. Class methods do not.
164: - The `user` parameter is always stripped from method tool specs -- it is
165:   injected server-side from JWT, never passed by the LLM.
166: - Parameter names with hyphens are converted to underscores. Invalid
167:   Python identifiers are skipped with a warning.
168: - Generated functions use `exec()` with a controlled namespace containing
169:   only `_route`, `_target`, `_method`, and `_required`. Input comes from
170:   trusted model schemas, not user data.
171: - Optional parameters set to `None` are stripped from the data dict before
172:   routing, but required parameters with `None` value are preserved. This
173:   prevents sending empty optional fields to CRUD operations.

24: ## 🚀 Quick Start
25: 
26: Here's the fun part — you write a couple of classes and get a working API with auth, relationships, and custom endpoints:
27:

40:     __tablename__ = 'products'
41:     __storable__ = True
42:     __access__ = {'read': ANYONE, 'create': AUTHENTICATED, 'update': OWNER, 'delete': ROLE('admin')}
43:     name: str = Field(min_length=1, max_length=200)
44:     price: float = Field(gt=0)
45:     comments: list[Comment] = Field(default=[])
46: 
47:     @expose_route('/like', methods=['POST'], access=AUTHENTICATED)

51: # One-liner: creates storage, registers models, generates routes, returns ASGI app

54:     storage="sqlite:///app.db",

60: ## 🧠 Core Concepts
61: 
62: ### The Model is the App
63: 
64: A `ProtoModel` subclass with `__storable__ = True` gets: a database table, CRUD API endpoints, a JSON Schema, authorization, and frontend rendering. `__init_subclass__` injects `StorableMixin` into the class hierarchy automatically. You don't wire anything up — it just works.
65: 
66: ### Schema Pipeline
67: 
68: `ProtoModel.schema()` runs a composable pipeline of `dict -> dict` stages: `base -> strip_hidden -> methods -> defs -> access -> widget -> ui -> metadata`. Each stage enriches the JSON Schema. External packages insert stages via `@schema_extension(after='methods')` without modifying core. Want to add your own stage? Slot it in wherever you need it.
69: 
70: ### Dump Pipeline
71: 
72: `instance.model_response()` runs a parallel pipeline for serialization: `base -> relationships -> schema_url -> instance_url -> populate`. The `relationships` stage enriches hydrated `T` and `list[T]` children through their own dump pipelines; the URL stages inject `$schema` and `$id`. Extended via `@dump_extension`. Same composable pattern, different direction — schema describes the shape, dump fills it with data.
73: 
74: ### 🔐 Authorization (ABAC)
75: 
76: The `authorize` subpackage is standalone (zero N3TX imports). Rules compose algebraically — and honestly, this is one of the coolest parts: `OWNER | ROLE('admin')`, `AUTHENTICATED & Where(status='published')`. Rules produce SQL WHERE clauses for list-level pushdown. Declared on models via `__access__` dict, on methods via `@expose_route(access=...)`.
77: 
78: ### 🔗 References and Relationships
79: 
80: Your models don't exist in isolation — they talk to each other:
81: 
82: `Ref[T]` for pointer fields (stored as local ids or canonical distributed refs, serialized as resolvable refs). `list[T]` for owned local collections (stored as ordered local ids, hydrated as child objects). `Ref['self']` for self-referential nesting. For shared relationship data, prefer explicit link models; `ManyToMany[T]` is a legacy helper for existing shared-link cases.

160: ## 📐 Patterns and Conventions
161: 
162: A few things worth knowing before you dive deeper:
163: 
164: 1. **Always set `__tablename__`** on storable models. It determines the API path (`/{tablename}`) and DB table name. Omitting it causes schema `$id` to fall back to the lowercase class name.
165: 
166: 2. **`model_dump()` for storage, `model_response()` for API.** `model_dump()` produces a plain dict. `model_response()` adds `$schema` and `$id` metadata via the dump pipeline. Never use `model_response()` data for storage writes.
167: 
168: 3. **Register every storable model.** `list[T]` collections store child ids, so both parent and child models need storage-backed registration.
169: 
170: ```python
171: register_model(Product, storage=db)
172: register_model(Comment, storage=db)
173: ```
174: 
175: 4. **Storable models require a storage backend.** Calling `register_model(M)` on a `__storable__ = True` model without passing `storage=` raises `ValueError`. Non-storable models can be registered without storage.
176: 
177: 5. **The authorize package has zero N3TX imports.** Do not add N3TX-specific logic to `authorize/`. The boundary is enforced by design. The route layer bridges auth to models via `_resolve_user()`.

10: 
11: ```

15:   2. Prepare model registrations (pure -- no side effects)

21:      - actor mode re-syncs Matrix children to the finalized registered model classes
22:      - view-capability hooks may add /{ClassName}/@... HTML routes
23:   8. Mount discovery endpoints (/_meta, /.well-known/agent.json)
24:   9. Mount static files (framework + app)
25:   |
26:   v
