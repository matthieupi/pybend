**Create `apps/veille/static/components/ntx-run-report.js`:**

A Web Component following the exact same patterns as `ntx-grant-analyze.js`:
- Shadow DOM with embedded styles
- Observed attribute: `run-id`
- `attributeChangedCallback` triggers `#loadReport()` when `run-id` changes
- No StreamActor mixin needed (this is a read-only view, not a streaming component). Extend plain `HTMLElement`.

**Component structure:**

```javascript
class NTXRunReport extends HTMLElement {
    #els;
    #runId = null;
    #report = null;

    static get observedAttributes() { return ['run-id']; }

    attributeChangedCallback(name, oldVal, newVal) {
        if (name === 'run-id' && newVal && newVal !== oldVal) {
            this.#runId = newVal;
            if (this.shadowRoot) this.#loadReport();
        }
    }

    connectedCallback() { /* attachShadow, render template, bind events */ }
}
```

**Template layout (in shadowRoot):**

- Panel header: "Run Report" title + "Back to Runs" button (navigates to `#runs`) + run status badge
- Run metadata bar: shows run type, started_at, completed_at, grants_found, sources_covered
- Summary counts bar: four colored count pills showing admissible / partial / non-admissible / new counts with totals
- Four collapsible sections (always visible, not collapsed by default):
  1. **Admissible** (green accent) -- grants sorted by score descending
  2. **Partially Admissible** (yellow/warning accent) -- grants sorted by score descending
  3. **Non-Admissible** (red accent) -- grants list
  4. **Unanalyzed** (gray accent) -- new grants not yet analyzed
- Each grant card in a section shows: title, funder, score (as percentage), deadline, and a truncated justification (admissibility_reasoning). The title is a clickable link to `#analyze/{grant_id}`.
- If a section has 0 grants, show "None" in muted text.
- Empty state: if run has no grants at all, show a placeholder message.

**`#loadReport()` method:**

```javascript
async #loadReport() {
    const token = localStorage.getItem('jwtToken');
    const resp = await fetch(`${config.API_URL}/runs/report?run_id=${this.#runId}`, {
        headers: { 'x-access-token': token },
    });
    if (!resp.ok) { /* show error */ return; }
    this.#report = await resp.json();
    this.#render();
}
```

**`#render()` method:**

Builds the full report HTML from `this.#report` data. Uses `marked.parse()` for admissibility_reasoning if `typeof marked !== 'undefined'`, otherwise plain text. Escape user-provided strings with the same `#esc()` helper pattern used in other components.

Also fetch run metadata to show in the header. The report endpoint from Plan 01 should include a `run` key with run metadata. If not available, fetch it separately via `GET /runs/{id}`.

**Styles:**

Follow the same visual language as ntx-run-panel and ntx-grant-analyze:
- Same font-family, font-size, color variables (--surface-1, --surface-2, --surface-3, --text-1, --text-2, --accent, --success, --warning, --error, --border)
- Same panel/header/footer pattern
- Grant cards: compact rows with score pill, title, funder, deadline
- Score pills: green for >= 0.7, yellow for >= 0.4, red for < 0.4
- Section headers with colored left borders matching their classification
- Responsive: single column on mobile, grid on wider screens

**`#loadHistory()` method:**

```javascript
async #loadHistory() {
    const token = localStorage.getItem('jwtToken');
    if (!token) return;

    try {
        const resp = await fetch(`${config.API_URL}/runs?limit=20`, {
            headers: { 'x-access-token': token },
        });
        if (!resp.ok) return;
        const result = await resp.json();
        const runs = result.data || result;

        // Sort by started_at descending (most recent first) -- Python-side sort
        runs.sort((a, b) => {
            const ta = a.started_at || '';
            const tb = b.started_at || '';
            return tb.localeCompare(ta);
        });

        this.#renderHistory(runs);
    } catch (e) {
        console.warn('Failed to load run history:', e);
    }
}
```

**`#renderHistory(runs)` method:**

Renders a table/list of runs with columns:
- **Run #** (id)
- **Type** (full/adhoc) -- with a pill style
- **Status** -- colored pill (complete=green, failed=red, running=blue, pending=gray)
- **Started** -- formatted date (short format, e.g., "Mar 20, 14:35")
- **Grants** -- grants_found count
- **Sources** -- sources_covered count
- **Actions** -- "View Report" link for completed runs only (links to `#report/{id}`)

If no runs exist, show "No runs yet. Start your first run above."

Each run row should be a `<div class="history-row">` (not a `<tr>`) for consistent styling.

**Date formatting helper:**
```javascript
#formatDate(iso) {
    if (!iso) return '--';
    try {
        const d = new Date(iso);
        return d.toLocaleDateString('en', { month: 'short', day: 'numeric' })
            + ', ' + d.toLocaleTimeString('en', { hour: '2-digit', minute: '2-digit' });
    } catch { return iso; }
}
```
